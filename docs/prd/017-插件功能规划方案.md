## 1. 规划目标与原则

### 1.1 规划目标

在 v2.32.1 现有基础上，于 3-6 个月内将插件推进至 v3.0，达成以下目标：

1. **质量巩固**：清零 016-上线前问题修复清单 中的 P0/P1 全部条目与关键 P2 资源泄漏
2. **性能与架构**：修复 DI 容器竞态、AST 缓存 TOCTOU、Map 无界增长等结构性问题，确保大 SQL（≥1MB）场景稳定可用
3. **功能补全**：补齐现有功能的明显缺口（断线重连、查询取消真实终止、导出加密、性能监控可视化等）
4. **能力拓展（最小可交付）**：在开发工具增强方向上交付事务管理面板与查询历史增强两项

### 1.2 设计原则

| 原则       | 说明                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| 复用优先   | 新功能必须复用现有 DIContainer / ModuleRegistry / IDatabaseAdapter / BaseWebviewPanel 体系，避免新增平行抽象 |
| YAGNI      | v3.0 仅交付最小可交付集，ER 图、SQL 文档生成等推后至 v3.x 探查                                               |
| 不退化基线 | 性能指标以 `perf.benchmark.*` 现有结果为基线，新版本不得退化（无严格数值阈值）                               |
| 安全前置   | 所有新增 Webview 必须包含 CSP、迁移 `addEventListener`、避免 `innerHTML` 拼接                                |
| 可测试性   | 每个新模块必须先写单测，复用 vscode-test + mocha 体系                                                        |
| 向后兼容   | 不破坏现有用户配置；新配置项必须有合理默认值                                                                 |

### 1.3 范围界定

**本规划包含**：

- v2.32.1 现有功能的全量盘点
- 4 个版本里程碑的功能与质量拆分
- 8 大主题的详细规划（功能清单 / 技术方案 / 优先级 / 集成 / UI / 性能 / 兼容性 / 测试）

**本规划不包含**（推后至 v3.x+）：

- AI 辅助能力（NL2SQL、SQL 优化建议、错误诊断）
- NoSQL 数据源（MongoDB、Redis、Elasticsearch 等）
- 更多 SQL 方言（DB2、Sybase、Teradata、DuckDB、Trino）
- ER 图、数据对比/同步、SQL 文档生成、版本控制集成

### 3.2 v2.34 性能与架构期

#### P-01: DI 容器单例创建竞态修复

**实现位置**：[src/core/diContainer.ts](file:///Users/hao/Downloads/sql-all-in-one/src/core/diContainer.ts)

**技术方案**：引入"正在创建中"中间状态标记，防止两个调用者同时触发工厂函数：

```typescript
private creating = new Set<string>();

get<T>(token: string): T | undefined {
    if (this.services.has(token)) return this.services.get(token) as T;
    if (this.singletons.has(token) && !this.creating.has(token)) {
        this.creating.add(token);
        try {
            const instance = (this.singletons.get(token) as () => T)();
            this.services.set(token, instance);
            return instance;
        } finally {
            this.creating.delete(token);
        }
    }
    if (this.factories.has(token)) return (this.factories.get(token) as () => T)();
    return undefined;
}
```

**注意**：单线程 JS 中"竞态"实质是递归 `get()` 导致的重复实例化（如 A 的工厂在初始化时 `get(B)`，而 B 又 `get(A)`）。修复后递归调用返回 `undefined`，调用方需做空检查。

#### P-02: AST 缓存 TOCTOU 修复

**实现位置**：[src/parser/DocumentAstCache.ts](file:///Users/hao/Downloads/sql-all-in-one/src/parser/DocumentAstCache.ts)

**技术方案**：将 `getOrParse` 改为原子操作，返回时同时持有缓存条目引用：

```typescript
getOrParse(document: TextDocument): { ast: AstNode; entry: AstCacheEntry } {
    const key = this.cacheKey(document);
    let entry = this.cache.get(key);
    if (!entry) {
        entry = { ast: this.parse(document), symbolIndex: new Map() };
        this.cache.set(key, entry);
    }
    return { ast: entry.ast, entry };
}
```

调用方通过返回的 `entry` 直接设置 `symbolIndex`，避免再次 `cache.get` 时已被 LRU 淘汰。

#### P-06: DI 容器 dispose 调用

```typescript
clear(): void {
    for (const instance of this.services.values()) {
        if (instance && typeof (instance as any).dispose === 'function') {
            try { (instance as any).dispose(); } catch (e) { console.error(e); }
        }
    }
    this.services.clear();
    this.singletons.clear();
    this.factories.clear();
}

unregister(token: string): void {
    const instance = this.services.get(token);
    if (instance && typeof (instance as any).dispose === 'function') {
        try { (instance as any).dispose(); } catch (e) { console.error(e); }
    }
    this.services.delete(token);
    this.singletons.delete(token);
    this.factories.delete(token);
}
```

### 3.3 v2.35 功能补全期

#### F-01: 断线自动重连机制

**实现位置**：[src/database/connection/ConnectionManager.ts](file:///Users/hao/Downloads/sql-all-in-one/src/database/connection/ConnectionManager.ts)

**技术方案**：

1. 在 `BaseConnectionAdapter` 中暴露 `on('connectionLost')` 事件
2. `ConnectionManager` 监听该事件，触发重连流程：
    - 第 1 次重连：立即
    - 第 2-N 次：指数退避（1s/2s/4s/8s/16s，上限 30s）
    - 最大重试次数：5（可配置 `hive-formatter.connection.maxReconnectAttempts`）
3. 重连期间状态为 `reconnecting`，触发 `onDidChangeConnectionState` 事件
4. UI 反馈：状态栏显示"重连中 (尝试 2/5)"，重连成功显示通知

**配置项**：

```json
{
    "hive-formatter.connection.maxReconnectAttempts": { "default": 5, "type": "number" },
    "hive-formatter.connection.reconnectBaseDelay": { "default": 1000, "type": "number" }
}
```

#### F-10: 导出加密

**实现位置**：[src/database/connection/ConnectionStore.ts](file:///Users/hao/Downloads/sql-all-in-one/src/database/connection/ConnectionStore.ts)

**技术方案**：`includePasswords = true` 时使用 VS Code SecretStorage 为主密钥的派生密钥进行 AES-256-GCM 加密：

```typescript
async exportConnections(filePath: string, includePasswords: boolean): Promise<void> {
    const data = this.serialize(includePasswords);
    if (includePasswords) {
        const encrypted = await this.encrypt(data);
        await fs.writeFile(filePath, JSON.stringify({ version: 2, encrypted }, null, 2));
    } else {
        await fs.writeFile(filePath, JSON.stringify({ version: 2, connections: data }, null, 2));
    }
    if (process.platform !== 'win32') await fs.chmod(filePath, 0o600);
}
```

**注意**：导入时根据 `version` 字段判断是否需要解密，保留对 v1 明文格式的向后兼容。

### 9.5 安全扫描

**v2.33 后**：在 CI 中增加安全扫描脚本：

1. **Webview CSP 检查**：扫描所有 HTML 文件，确认包含 CSP meta
2. **innerHTML 检查**：扫描 Webview JS 文件，警告 `innerHTML` 拼接
3. **SQL 注入检查**：扫描 `adapter.execute(` 调用，确认参数使用占位符而非字符串拼接
4. **密码明文检查**：扫描 `password` 字段使用，确认不写入日志或明文存储

**实现位置**：新建 `scripts/security-scan.ts`，在 `package.json` 的 `scripts` 中增加：

```json
"security:scan": "tsx scripts/security-scan.ts"
```

### 9.6 CI 流水线

**`.github/workflows/ci.yml` 增强**：

```yaml
jobs:
  lint:
    - run: npm run lint          # oxlint
    - run: npm run format:check # oxfmt
  typecheck:
    - run: npm run compile      # tsc --noEmit
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    - run: npm test             # vscode-test
  security:
    - run: npm run security:scan
  perf:
    - run: npm run perf:benchmark

```

**需在 `package.json` 的 `scripts` 中新增**：

```json
"security:scan": "tsx scripts/security-scan.ts",

```
