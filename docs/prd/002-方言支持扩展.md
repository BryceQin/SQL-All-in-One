## 1. 功能概览

本次 P0 迭代目标是将插件从"4 种方言基础支持"扩展到"10 种方言全面支持"，同时深化现有功能的方言感知能力。

| 模块 | 内容 | 用户感知强度 |
|------|------|-------------|
| M1 | 新增 PostgreSQL、Oracle、BigQuery、Snowflake、Presto、SQLite 共 6 种方言的格式化支持 | ★★★★★ |
| M2 | 代码片段按方言拆分；关键字/数据类型/函数补全覆盖全部 10 种方言 | ★★★★☆ |
| M3 | 诊断规则方言化：现有规则感知方言差异 + 新增 20+ 条方言专属规则 | ★★★☆☆ |
| M4 | 现有 4 种方言的能力补齐（语言 ID 注册、提供者注册、配置完善） | ★★★☆☆ |
| M5 | 为全部 10 种方言注册 VSCode 语言 ID、文件扩展名、配置 | ★★★★★ |

### 不做

- 新增方言互转（转换器保持现有 Hive↔MySQL 双向转换，不扩展）

## 2. 架构现状

插件当前方言系统架构（详细代码参考项目源码）：

| 维度 | 当前状态 |
|------|---------|
| 支持方言 | Hive、MySQL、Spark、SQL（4 种） |
| 方言定义 | 每种 3 文件：`<dialect>.formatter.ts`、`<dialect>.keywords.ts`、`<dialect>.functions.ts` |
| 核心架构 | `DialectOptions` → `createDialect()` → `Tokenizer` + `FormatOptions`，依赖注入模式 |
| VSCode 语言注册 | 仅注册 `sql(.sql)` 和 `hive(.hql)`，MySQL 和 Spark 无独立语言 ID |
| 代码片段 | 所有方言共用 `snippets/sql.json`（16 个片段） |
| 诊断规则 | 全部使用通用 SQL 假设，不区分方言差异 |
| 转换器 | 仅支持 MySQL↔Hive 双向转换 |

新增方言只需遵循现有 `DialectOptions` 接口填充配置即可，架构本身无需修改。

### 3.2 各方言词法分析器关键差异

覆盖 `TokenizerOptions` 中 20+ 个配置维度，下面列出各方言与默认 SQL 的关键差异：

#### 3.2.1 PostgreSQL

| 配置项 | 值 |
|---|---|
| `stringTypes` | `''-qq-bs`（标准）、`E''-bs`（转义字符串）、`U&''`（Unicode 字符串）、`$$...$$`（Dollar Quoting） |
| `identTypes` | `""-qq`、`` ` `` |
| `lineCommentTypes` | `["--"]` |
| `reservedSetOperations` | `UNION [ALL\|DISTINCT]`、`INTERSECT [ALL\|DISTINCT]`、`EXCEPT [ALL\|DISTINCT]` |
| `extraParens` | `["[]"]`（ARRAY 字面量） |
| `operators` | `::`（类型转换）、`->`/`->>`/`#>`/`#>>`（JSON 操作符）、`@>`/`<@`（包含）、`?`/`?\|`/`?&`（JSON 存在）、`~`/`~*`/`!~`/`!~*`（正则匹配）、`@@`/`@@@`（全文搜索）、`\|\|`（字符串拼接） |
| `variableTypes` | `:` 前缀（psql 变量） |
| 独有子句 | `RETURNING`、`ON CONFLICT`、`DISTINCT ON`、`FOR UPDATE/SHARE`、`FETCH FIRST/NEXT`、`WINDOW`、`LATERAL`、`TABLESAMPLE`、`WITH ORDINALITY`、`FILTER (WHERE ...)` |
| `postProcess` | 需要：`::` 类型转换与运算符的消歧义 |

#### 3.2.2 Oracle

| 配置项 | 值 |
|---|---|
| `stringTypes` | `''-qq-bs`、`q'[...]'`（替代引号机制） |
| `identTypes` | `""-qq` |
| `lineCommentTypes` | `["--"]` |
| `reservedSetOperations` | `UNION [ALL]`、`INTERSECT`、`MINUS` |
| `operators` | `\|\|`（字符串拼接）、`:=`（赋值）、`**`（幂运算）、`(+)`（旧式外连接符号） |
| `variableTypes` | `:` 前缀（绑定变量）、`&` 前缀（替换变量） |
| 独有子句 | `CONNECT BY`、`START WITH`、`MERGE`、`RETURNING INTO`、`BULK COLLECT INTO`、`MODEL`、`FOR UPDATE [WAIT\|NOWAIT]`、`FLASHBACK`、`VERSIONS BETWEEN`、`HIERARCHICAL QUERY` |
| 特殊行为 | 表别名不支持 `AS` 关键字（`SELECT * FROM t a` 而非 `FROM t AS a`） |
| `postProcess` | 需要：`(+)` 外连接符号识别、表别名无 AS 处理 |

#### 3.2.3 BigQuery

| 配置项 | 值 |
|---|---|
| `stringTypes` | `''-bs`、`""-bs`、`r''`（raw string）、`b''`（bytes literal）、`'''...'''`（三引号字符串） |
| `identTypes` | `` ` ``（反引号） |
| `lineCommentTypes` | `["--", "#"]` |
| `reservedSetOperations` | `UNION [ALL\|DISTINCT]`、`INTERSECT [ALL\|DISTINCT]`、`EXCEPT [ALL\|DISTINCT]` |
| `operators` | 标准 SQL 运算符 |
| 独有子句 | `CREATE OR REPLACE`、`MERGE`、`PIVOT`、`UNPIVOT`、`QUALIFY`、`TABLESAMPLE`、`FOR SYSTEM_TIME AS OF`、`OPTIONS(...)` |
| `postProcess` | 可能需要：`SELECT AS STRUCT/VALUE` 特殊语法处理 |

#### 3.2.4 Snowflake

| 配置项 | 值 |
|---|---|
| `stringTypes` | `''-bs`、`$$...$$` |
| `identTypes` | `""-qq` |
| `lineCommentTypes` | `["--", "//"]` |
| `reservedSetOperations` | `UNION [ALL]`、`INTERSECT`、`MINUS`/`EXCEPT`（两者都支持） |
| `operators` | `::`（类型转换） |
| `variableTypes` | `?`（位置参数）、`:name`（命名参数） |
| `paramTypes` | `{ named: [":"], positional: true }` |
| 独有子句 | `QUALIFY`、`SAMPLE`/`TABLESAMPLE`、`LATERAL FLATTEN`、`MATCH_RECOGNIZE`、`CONNECT BY`、`PIVOT`、`UNPIVOT`、`CLUSTER BY`、`COPY INTO`、`STAGE`、`FILE FORMAT` |

#### 3.2.5 Presto

| 配置项 | 值 |
|---|---|
| `stringTypes` | `''-bs` |
| `identTypes` | `""-qq`、`` ` `` |
| `lineCommentTypes` | `["--"]` |
| `reservedSetOperations` | `UNION [ALL\|DISTINCT]`、`INTERSECT [ALL\|DISTINCT]`、`EXCEPT [ALL\|DISTINCT]` |
| `operators` | `->`（Lambda 箭头） |
| 独有子句 | `CROSS JOIN UNNEST`、`LATERAL`、`AT TIME ZONE`、`MATCH_RECOGNIZE`、`WITH ORDINALITY` |
| 类型构造语法 | `ARRAY(VARCHAR)`、`MAP(VARCHAR, INT)` 等函数式类型构造 |
| `postProcess` | 可能需要：Lambda `->` 与运算符的区分 |

#### 3.2.6 SQLite

| 配置项 | 值 |
|---|---|
| `stringTypes` | `''-qq`（双单引号转义，默认不支持反斜杠转义） |
| `identTypes` | `""-qq`、`` ` ``、`[]` |
| `lineCommentTypes` | `["--"]` |
| `reservedSetOperations` | `UNION [ALL]`、`INTERSECT`、`EXCEPT` |
| `operators` | `\|\|`（字符串拼接）、`->`/`->>`（JSON 操作符） |
| 独有子句 | `ON CONFLICT`（UPSERT 语法）、`RETURNING`（3.35.0+） |
| 不支持 | `RIGHT OUTER JOIN`、`FULL OUTER JOIN` |
| 类型系统 | 类型亲和性（Type Affinity），非强制类型检查；`ANY` 类型 |
| `postProcess` | 不需要 |

## 4. M2 - 补全方言化

### 4.1 代码片段按方言拆分

#### 4.1.1 问题

当前所有方言共用 `snippets/sql.json`，导致 Hive 特有片段（如 `hivepart`、`hiveselpart`）在 MySQL/SQL 模式下也会出现。

#### 4.1.2 解决方案

将单一文件拆分为方言专属文件 + 通用公共文件：

```
snippets/
├── common.json          # 通用片段（SELECT、FROM、WHERE、INSERT 等基础 SQL 模板）
├── hive.json            # Hive 特有
├── mysql.json           # MySQL 特有
├── spark.json           # Spark 特有
├── sql.json             # 标准 SQL 特有
├── postgresql.json      # PostgreSQL 特有
├── oracle.json          # Oracle/PLSQL 特有
├── bigquery.json        # BigQuery 特有
├── snowflake.json       # Snowflake 特有
├── presto.json          # Presto 特有
└── sqlite.json          # SQLite 特有
```

#### 4.1.3 合并策略

- 对当前文档的方言：加载 `common.json` + `<dialect>.json`
- 如果方言没有专属文件：仅加载 `common.json`
- 提供配置项允许用户关闭通用片段或专属片段

#### 4.1.4 package.json 注册


#### 4.1.5 common.json 通用片段内容

所有方言共享的基础 SQL 模板（从现有 `sql.json` 中提取方言无关的片段）：

| prefix | 名称 | 内容简述 |
|---|---|---|
| `sel` | SELECT 查询 | `SELECT ${1:columns} FROM ${2:table} WHERE ${3:condition}` |
| `self` | SELECT FROM | `SELECT ${1:columns} FROM ${2:table}` |
| `selj` | SELECT with JOIN | `SELECT ... FROM t1 JOIN t2 ON ...` |
| `selw` | SELECT with WHERE | `SELECT ... FROM ... WHERE ...` |
| `selg` | SELECT with GROUP BY | `SELECT ... FROM ... GROUP BY ...` |
| `selo` | SELECT with ORDER BY | `SELECT ... FROM ... ORDER BY ...` |
| `ins` | INSERT INTO | `INSERT INTO ${1:table} (${2:columns}) VALUES (${3:values})` |
| `insv` | INSERT FROM SELECT | `INSERT INTO ${1:target} SELECT ... FROM ${2:source}` |
| `upd` | UPDATE | `UPDATE ${1:table} SET ${2:col} = ${3:value} WHERE ${4:condition}` |
| `del` | DELETE | `DELETE FROM ${1:table} WHERE ${2:condition}` |
| `crt` | CREATE TABLE | `CREATE TABLE ${1:name} (${2:columns})` |
| `cte` | WITH (CTE) | `WITH ${1:cte_name} AS (${2:query}) SELECT ...` |
| `case` | CASE WHEN | `CASE WHEN ${1:condition} THEN ${2:value} ELSE ${3:default} END` |
| `subq` | Subquery | `(SELECT ${1:columns} FROM ${2:table})` |

### 4.4 标识符/CTE 补全

现有方言无关的标识符补全（表名/列名推断）和 CTE 名称补全逻辑保持不变，因为它们基于 SQL 文本通用解析，不依赖方言配置。

### 4.5 各方言专属片段详情

每种方言至少提供 5-10 个高频使用模板。

#### 4.5.1 PostgreSQL 专属片段 (`postgresql.json`)

| prefix | 名称 | 内容 |
|---|---|---|
| `pgfunc` | CREATE FUNCTION | `CREATE OR REPLACE FUNCTION ${1:name}(${2:params}) RETURNS ${3:type} LANGUAGE ${4:plpgsql} AS $$ BEGIN ${5:body} END; $$` |
| `pgret` | RETURNING | `INSERT INTO ${1:table} ${2:columns} VALUES (${3:values}) RETURNING *` |
| `pgconflict` | ON CONFLICT (UPSERT) | `INSERT INTO ${1:table} (${2:columns}) VALUES (${3:values}) ON CONFLICT (${4:constraint}) DO UPDATE SET ${5:updates}` |
| `pgilike` | ILIKE | `${1:column} ILIKE '%${2:pattern}%'` |
| `pgjson` | JSON 查询 | `SELECT ${1:data}->'${2:key}', ${1:data}->>'${2:key}' FROM ${3:table}` |
| `pgcast` | 类型转换 | `${1:value}::${2:type}` |

## 5. M3 - 诊断规则方言化

### 5.1 当前问题分析

当前三个诊断文件（`SqlDiagnosticsProvider`、`EnhancedSqlChecker`、`SqlLinter`）使用硬编码的通用 SQL 假设，不感知当前方言：

| 问题类别 | 具体表现 | 影响方言 |
|---|---|---|
| 保留字列表不区分 | `checkReservedWordIdentifiers` 用通用 45 词列表，但 PG 保留字与 SQLite 差异大 | 所有 |
| 方言特有函数提示不全 | `checkDateFunctionUsage` 仅覆盖 Hive↔MySQL 差异 | PG/Oracle/BQ/SF/Presto |
| 语法假设不通用 | `checkSelectWithoutFrom` 不识别 Oracle DUAL | Oracle |
| 规则前提不适配 | `checkEmptyJoin` 只要求 ON，但 USING 和 NATURAL JOIN 合法 | 所有 |
| 子查询别名不适配 | `checkSubqueryWithoutAlias` 强制要求别名，但 Oracle/SQLite 不强制 | Oracle/SQLite |
| 列注释格式不兼容 | `checkMissingColumnComment` 只识别 `COMMENT '...'`，PG/Oracle 用 `COMMENT ON COLUMN` | PG/Oracle |

### 5.2 架构设计

在诊断流程中注入方言上下文：

```
SqlDiagnosticsProvider
├── 通用规则（方言无关，不变）
│   └── 括号匹配、未闭合字符串、逗号检测等
├── 方言感知规则（改造）
│   ├── EnhancedSqlChecker(dialect)   ← 接收方言参数
│   └── SqlLinter(dialect)            ← 接收方言参数
└── 方言专属规则（新增）
    └── 仅特定方言启用的专属规则
```

### 5.3 现有规则方言感知改造

#### 5.3.1 保留字检测 - 按方言加载

将 `checkReservedWordIdentifiers` 从硬编码列表改为按方言加载对应的保留字列表。利用现有的 `<dialect>.keywords.ts` 中已定义的关键字数组。

#### 5.3.2 日期/时间函数提示 - 扩展到所有方言

将 `checkDateFunctionUsage` 从仅 Hive↔MySQL 扩展为覆盖全部 10 种方言：

| 当前方言 | 检测到的函数 | 提示内容 |
|---|---|---|
| Hive | `NOW()`, `SYSDATE()`, `GETDATE()` | 建议使用 `CURRENT_TIMESTAMP()` |
| MySQL | `GETDATE()` | 建议使用 `NOW()` 或 `CURRENT_TIMESTAMP()` |
| PostgreSQL | `SYSDATE()` | 不存在于 PG，建议 `CLOCK_TIMESTAMP()` 或 `NOW()` |
| Oracle | `NOW()` | 不存在于 Oracle，建议 `SYSDATE` 或 `CURRENT_TIMESTAMP` |
| BigQuery | `SYSDATE()`, `GETDATE()` | 不存在于 BQ，建议 `CURRENT_TIMESTAMP()` |
| Snowflake | `SYSDATE()`, `GETDATE()` | 不存在于 SF，建议 `CURRENT_TIMESTAMP()` |
| Presto | `SYSDATE()`, `GETDATE()` | 建议 `CURRENT_TIMESTAMP` 或 `NOW()` |
| SQLite | `SYSDATE()`, `GETDATE()` | 不存在于 SQLite，建议 `datetime('now')` 或 `CURRENT_TIMESTAMP` |

#### 5.3.3 SELECT without FROM - 按方言调整

| 方言 | 允许无 FROM 的场景 |
|---|---|
| Hive/Spark/SQL | `SELECT CURRENT_TIMESTAMP` 等系统函数调用 |
| MySQL | `SELECT 1`, `SELECT NOW()` 等表达式 |
| PostgreSQL | `SELECT 1+1`, `SELECT setval(...)`, 函数表达式 |
| Oracle | `SELECT ... FROM DUAL`（识别 DUAL 表作为 FROM 表则不算错误） |
| BigQuery/Snowflake | `SELECT 1`, `SELECT CURRENT_TIMESTAMP()` |
| Presto | `SELECT 1`, `SELECT CURRENT_TIMESTAMP` |
| SQLite | `SELECT 1`, `SELECT datetime('now')` |

#### 5.3.4 子查询别名要求 - 按方言区分

| 方言 | 是否需要子查询别名 | 规则行为 |
|---|---|---|
| Hive/MySQL/Spark/SQL/BigQuery/Snowflake/Presto | **必须** | 启用检查，缺别名时报 Warning |
| Oracle | **不强制** | 关闭检查（不报） |
| SQLite | **不强制** | 关闭检查（不报） |

#### 5.3.5 JOIN 条件检测 - 按方言扩展

`checkEmptyJoin` 当前只检测 `ON` 缺失，需扩展识别以下合法无 ON 的 JOIN 形式：

- `JOIN ... USING (column)` — 所有方言支持，合法
- `NATURAL JOIN` — PostgreSQL、MySQL、SQLite、Presto 支持；Hive、BigQuery 不支持（需报警告）
- `CROSS JOIN` — 明确不需要 ON，合法

#### 5.3.6 列注释检测 - 按方言适配

`checkMissingColumnComment` 当前只识别内联 `col_name TYPE COMMENT '...'` 格式：

| 方言 | COMMENT 语法格式 | 检测方式 |
|---|---|---|
| Hive/Spark/MySQL/Snowflake | `col_name TYPE COMMENT '...'` | 现有逻辑不变 |
| PostgreSQL | `COMMENT ON COLUMN table.col IS '...'`（独立语句） | 新增独立 COMMENT ON 语句检测 |
| Oracle | `COMMENT ON COLUMN table.col IS '...'`（独立语句） | 新增独立 COMMENT ON 语句检测 |
| BigQuery | `col_name TYPE OPTIONS(description='...')` | 新增 OPTIONS(description=) 格式检测 |
| Presto | 不支持列级 COMMENT | 该规则默认关闭 |
| SQLite | 不支持列级 COMMENT | 该规则默认关闭 |

## 10. 非功能需求

| 需求 | 说明 |
|------|------|
| 兼容性 | 现有用户配置文件保持兼容，`SQL-All-in-One.dialect` 默认值仍为 `"hive"` |
| 性能 | 新增方言的文件加载采用懒加载，不在启动时全量加载所有方言配置 |
| 可扩展性 | 新增方言只需添加 3 个配置文件 + 注册映射，无需修改核心架构 |
| 回退安全 | 未知方言自动回退到默认 `hive` 方言，不阻塞用户使用 |
| 代码组织 | 每种方言的配置、关键字、函数、片段、lint 规则均放在独立文件中，职责清晰 |
| 文档同步 | `README.md` 和 `package.json` 的 `description` 中更新支持的方言列表 |

### 文件变更汇总

| 变更类型 | 数量 | 说明 |
|---|---|---|
| 新增文件 | ~26 | 6方言×3配置文件(18) + 6方言专属片段(6) + common片段(1) + 方言专属lint规则(1) |
| 改造文件 | ~7 | allDialects.ts, sqlDialects.ts, extension.ts, package.json, SqlCompletionProvider.ts, EnhancedSqlChecker.ts, SqlLinter.ts |
| 不变 | 其余 | 核心架构（DialectOptions, Tokenizer, Formatter, Parser）无需修改 |
