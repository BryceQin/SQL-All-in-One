## 2. P0-1：适配器接口与类型定义

### 2.1 背景与问题

项目需要支持多种数据库（首期 MySQL，后续 PostgreSQL、SQLite 等），必须定义统一的操作接口，让上层代码不感知底层数据库差异。这与项目现有的 `dialectRegistry` + 适配器模式一脉相承。

### 2.2 功能需求

#### 2.2.1 适配器接口分层设计

为了更好地符合单一职责原则，将适配器接口拆分为多个职责明确的接口：

**IConnectionAdapter** - 连接管理
| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `connect` | `config: ConnectionConfig` | `Promise<void>` | 建立数据库连接 |
| `disconnect` | 无 | `Promise<void>` | 断开数据库连接 |
| `isConnected` | 无 | `boolean` | 返回当前连接状态 |
| `testConnection` | `config: ConnectionConfig` | `Promise<TestConnectionResult>` | 测试连接是否可用 |
| `checkConnectionHealth` | 无 | `Promise<boolean>` | 检查连接健康状态 |
| `getConnectionId` | 无 | `string` | 获取当前连接ID |

**IQueryAdapter** - SQL执行
| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `execute` | `sql: string, params?: QueryParam[]` | `Promise<QueryResult>` | 执行查询/更新 SQL（统一入口） |
| `executeBatch` | `statements: SqlStatement[]` | `Promise<QueryResult[]>` | 批量执行SQL |
| `beginTransaction` | 无 | `Promise<void>` | 开始事务 |
| `commit` | 无 | `Promise<void>` | 提交事务 |
| `rollback` | 无 | `Promise<void>` | 回滚事务 |
| `cancelQuery` | `queryId: string` | `Promise<void>` | 取消正在执行的查询 |

**IMetadataAdapter** - 元数据查询
| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `listDatabases` | 无 | `Promise<DatabaseInfo[]>` | 列出所有数据库 |
| `listSchemas` | `database: string` | `Promise<string[]>` | 列出 Schema |
| `listTables` | `database, schema?, filter?` | `Promise<TableInfo[]>` | 列出表 |
| `listViews` | `database, schema?` | `Promise<ViewInfo[]>` | 列出视图 |
| `listFunctions` | `database, schema?` | `Promise<FunctionInfo[]>` | 列出函数 |
| `listProcedures` | `database, schema?` | `Promise<ProcedureInfo[]>` | 列出存储过程 |
| `listTriggers` | `database, schema?` | `Promise<TriggerInfo[]>` | 列出触发器 |

**ISchemaAdapter** - Schema操作
| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `describeTable` | `database, table, schema?` | `Promise<TableStructure>` | 获取表完整结构 |
| `getTableDDL` | `database, table, schema?` | `Promise<string>` | 获取建表 DDL |
| `getViewDDL` | `database, view, schema?` | `Promise<string>` | 获取视图定义 |
| `getExplainPlan` | `database, sql` | `Promise<ExplainResult>` | 获取执行计划 |
| `getTableRowCount` | `database, table, schema?` | `Promise<number>` | 获取表行数 |
| `getDialectCapabilities` | 无 | `DialectCapabilities` | 获取方言能力集 |
| `getSupportedDataTypes` | 无 | `DataTypeCategory[]` | 获取方言支持的数据类型列表（供表设计器使用） |

**IDatabaseAdapter** - 主适配器接口（组合上述接口）
```typescript
interface IDatabaseAdapter extends 
  IConnectionAdapter, 
  IQueryAdapter, 
  IMetadataAdapter, 
  ISchemaAdapter {
  // 组合接口，无需额外方法
}
```

> **接口设计说明**：`execute` 方法统一了 `executeQuery` 和 `executeUpdate`。适配器通过 SQL 前缀（SELECT/SHOW/DESCRIBE/EXPLAIN 视为查询，其余视为更新）或 `StatementType` 判断返回类型。上层调用方可通过 `QueryResult.status` 和 `affectedRows` 字段区分。`getSupportedDataTypes` 为表设计器（PRD-014）提供方言特定的数据类型列表。

#### 2.2.2 核心类型定义

**查询结果类型**：

| 类型 | 关键字段 | 说明 |
|------|---------|------|
| `QueryResult` | `queryId, status, columns, rows, rowCount, affectedRows?, executionTime, error?, database` | 查询执行结果 |
| `QueryError` | `code, message, sql?, position?` | 查询错误 |
| `ColumnMeta` | `name, type, nullable, isPrimaryKey, isAutoIncrement, isEnum, enumValues?, referencedTable?, comment?` | 列元数据 |
| `UpdateResult` | `affectedRows, insertId?, changedRows` | 更新执行结果 |

**数据库对象类型**：

| 类型 | 关键字段 | 说明 |
|------|---------|------|
| `DatabaseInfo` | `name, charset?, collation?` | 数据库信息 |
| `TableInfo` | `name, type, engine?, rowCount?, comment?` | 表信息 |
| `ViewInfo` | `name, definition?, comment?` | 视图信息 |
| `FunctionInfo` | `name, returns?, definition?` | 函数信息 |
| `ProcedureInfo` | `name, definition?` | 存储过程信息 |
| `TriggerInfo` | `name, event, timing, statement` | 触发器信息 |

**表结构类型**：

| 类型 | 关键字段 | 说明 |
|------|---------|------|
| `TableStructure` | `columns, indexes, foreignKeys, triggers, ddl, rowCount, engine?, charset?, comment?` | 完整表结构 |
| `ColumnInfo` | `name, type, length?, nullable, defaultValue?, isPrimaryKey, isAutoIncrement, isUnique, comment?, enumValues?, referencedTable?` | 列信息 |
| `IndexInfo` | `name, type, columns, isUnique, isPrimary` | 索引信息 |
| `ForeignKeyInfo` | `name, columns, referencedTable, referencedColumns, onDelete, onUpdate` | 外键信息 |

**方言能力类型**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `supportsSchema` | `boolean` | 是否支持 Schema 概念 |
| `supportsMultipleDatabases` | `boolean` | 是否支持多数据库 |
| `maxConcurrentQueries` | `number` | 最大并发查询数 |
| `supportsPreparedStatement` | `boolean` | 是否支持预处理语句 |
| `supportsExplain` | `boolean` | 是否支持 EXPLAIN |
| `supportsExplainAnalyze` | `boolean` | 是否支持 EXPLAIN ANALYZE |
| `supportsCancel` | `boolean` | 是否支持取消查询 |
| `supportsSshTunnel` | `boolean` | 是否支持 SSH 隧道 |
| `supportedObjectTypes` | `ObjectType[]` | 支持的对象类型列表 |

**数据类型分类**（供表设计器使用）：

| 类型 | 关键字段 | 说明 |
|------|---------|------|
| `DataTypeCategory` | `category, types` | 数据类型分类（如"整数"包含 TINYINT/INT/BIGINT） |
| `DataTypeInfo` | `name, needsLength?, needsPrecision?, needsScale?, defaultValue?` | 单个数据类型信息 |

**执行计划类型**：

| 类型 | 关键字段 | 说明 |
|------|---------|------|
| `ExplainResult` | `format, raw, nodes` | 执行计划结果 |
| `ExplainNode` | `id, operation, table?, rows?, cost?, key?, extra?, children` | 执行计划节点 |

#### 2.2.3 适配器工厂

| 方法 | 说明 |
|------|------|
| `AdapterFactory.register(dialect, AdapterClass)` | 注册适配器类 |
| `AdapterFactory.create(dialect, config: ConnectionConfig)` | 根据连接配置创建适配器实例 |
| `AdapterFactory.has(dialect)` | 检查方言是否已注册 |
| `AdapterFactory.getRegisteredDialects()` | 获取已注册方言列表 |

未注册方言调用 `create` 时抛出错误：`No adapter registered for dialect: {dialect}`。

## 3. P0-2：MySQL 适配器实现

### 3.1 背景与问题

需要实现第一个具体的数据库适配器——MySQL，作为后续所有功能的数据访问层。

### 3.2 功能需求

#### 3.2.1 技术规格

| 项目 | 规格 |
|------|------|
| 驱动 | `mysql2/promise` |
| 连接方式 | 连接池（`mysql2.createPool`） |
| 连接池大小 | 默认 5（与 ConnectionPoolConfig.maxConnections 一致），可通过 `ConnectionConfig.options.poolSize` 配置 |
| 连接超时 | 默认 10000ms，可通过 `ConnectionConfig.connectTimeout` 配置 |
| 字符集 | 默认 `utf8mb4`，可通过 `ConnectionConfig.options.charset` 配置 |
| 时区 | 默认本地时区，可通过 `ConnectionConfig.options.timezone` 配置 |

#### 3.2.2 MySQL 特定 SQL 映射

| 方法 | 执行的 SQL |
|------|-----------|
| `testConnection` | `SELECT VERSION()` |
| `listDatabases` | `SHOW DATABASES` |
| `listTables` | `SHOW TABLE STATUS FROM ?` |
| `listViews` | `SHOW FULL TABLES FROM ? WHERE Table_type = 'VIEW'` |
| `listFunctions` | `SHOW FUNCTION STATUS WHERE Db = ?` |
| `listProcedures` | `SHOW PROCEDURE STATUS WHERE Db = ?` |
| `listTriggers` | `SHOW TRIGGERS FROM ?` |
| `describeTable` | `SHOW COLUMNS FROM ?` + `SHOW INDEX FROM ?` + `SHOW TABLE STATUS LIKE ?` |
| `getTableDDL` | `SHOW CREATE TABLE ?` |
| `getViewDDL` | `SHOW CREATE VIEW ?` |
| `getExplainPlan` | `EXPLAIN FORMAT=JSON ?` |
| `getTableRowCount` | `SHOW TABLE STATUS LIKE ?`（取 Rows 列近似值，大表不 COUNT） |

#### 3.2.3 MySQL 方言能力

| 能力 | 值 |
|------|---|
| `supportsSchema` | `false` |
| `supportsMultipleDatabases` | `true` |
| `maxConcurrentQueries` | `5` |
| `supportsPreparedStatement` | `true` |
| `supportsExplain` | `true` |
| `supportsExplainAnalyze` | `false` |
| `supportsCancel` | `true`（通过 `KILL QUERY`） |
| `supportsSshTunnel` | `true` |
| `supportedObjectTypes` | `['table', 'view', 'function', 'procedure', 'trigger', 'index']` |

#### 3.2.4 连接池管理

- `connect()`: 创建连接池，执行 `SELECT 1` 验证连接可用
- `disconnect()`: 调用 `pool.end()` 关闭连接池
- `isConnected()`: 检查连接池是否存在且未关闭
- 连接池配置从 `ConnectionConfig` 中提取

#### 3.2.5 结果解析

- `execute()`: 将 `mysql2` 返回结果转换为 `QueryResult`（含 `columns`/`rows`/`affectedRows`）
- `listTables()`: 解析 `SHOW TABLE STATUS` 结果，提取表名、引擎、行数、注释
- `describeTable()`: 组合多查询结果构建完整 `TableStructure`
- `getTableDDL()`: 从 `SHOW CREATE TABLE` 结果中提取 `Create Table` 列

### 3.3 验收标准

- [ ] 安装 `mysql2` 依赖
- [ ] `MysqlAdapter` 实现 `IDatabaseAdapter` 全部方法
- [ ] 连接池正确创建和销毁
- [ ] `testConnection` 返回数据库版本和延迟
- [ ] 所有 `list*` 方法正确解析 MySQL 返回结果
- [ ] `describeTable` 组合多查询返回完整 `TableStructure`
- [ ] `AdapterFactory.register('mysql', MysqlAdapter)` 注册成功

## 5. P0-4：连接存储

### 5.1 背景与问题

连接配置需要持久化存储，且密码不能明文保存。采用混合方案：元数据存文件、密码存 SecretStorage。

### 5.2 功能需求

#### 5.2.1 存储方案

| 数据 | 存储位置 | 格式 |
|------|---------|------|
| 连接元数据（不含密码） | `~/.sql-all-in-one/connections.json` | JSON |
| 数据库密码 | VSCode SecretStorage | Key: `sql-all-in-one.password.{connectionId}` |
| SSH 密码 | VSCode SecretStorage | Key: `sql-all-in-one.ssh.password.{connectionId}` |
| SSH 私钥密码 | VSCode SecretStorage | Key: `sql-all-in-one.ssh.passphrase.{connectionId}` |

#### 5.2.2 connections.json 结构

```json
{
  "version": 1,
  "groups": [
    { "name": "开发环境", "color": "#4CAF50" },
    { "name": "测试环境", "color": "#FF9800" },
    { "name": "生产环境", "color": "#F44336" }
  ],
  "connections": [
    {
      "id": "uuid-xxx",
      "name": "开发库-MySQL",
      "dialect": "mysql",
      "group": "开发环境",
      "color": "#4CAF50",
      "host": "127.0.0.1",
      "port": 3306,
      "username": "root",
      "database": "mydb",
      "ssl": { "enabled": false },
      "ssh": { "enabled": false },
      "connectTimeout": 10000
    }
  ]
}
```

#### 5.2.3 连接空闲管理

为应对数据库服务端自动断开空闲连接（如 MySQL `wait_timeout` 默认 8 小时），连接管理器需实现心跳保持：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `sql-all-in-one.connection.idleTimeout` | `number` | `1800000` (30min) | 空闲超时自动断开(ms)，设为 0 禁用 |
| `sql-all-in-one.connection.keepAliveInterval` | `number` | `300000` (5min) | 心跳保持间隔(ms)，执行 `SELECT 1` 保持连接活跃 |

心跳策略：
- 对已连接的每个适配器，按 `keepAliveInterval` 定期执行轻量查询（如 `SELECT 1`）
- 心跳失败连续 2 次后，状态标记为 Error，触发自动重连机制
- 空闲超过 `idleTimeout` 的适配器自动断开，释放数据库连接资源

#### 5.2.4 ConnectionStore API

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `load` | 无 | `Promise<void>` | 从文件加载，不存在则创建默认文件 |
| `save` | 无 | `Promise<void>` | 保存到文件 |
| `addConnection` | `config` | `Promise<void>` | 添加连接（不含密码） |
| `removeConnection` | `id` | `Promise<void>` | 删除连接 |
| `updateConnection` | `id, config` | `Promise<void>` | 更新连接 |
| `getConnections` | 无 | `ConnectionConfig[]` | 返回所有连接 |
| `getConnection` | `id` | `ConnectionConfig?` | 返回指定连接 |
| `getGroups` | 无 | `ConnectionGroup[]` | 返回所有分组 |
| `addGroup` | `group` | `Promise<void>` | 添加分组 |
| `removeGroup` | `name` | `Promise<void>` | 删除分组 |
| `updateGroup` | `name, group` | `Promise<void>` | 更新分组 |
| `exportConnections` | `filePath, includePasswords` | `Promise<void>` | 导出连接配置 |
| `importConnections` | `filePath` | `Promise<ImportResult>` | 导入连接配置 |

#### 5.2.5 安全要求

- 文件权限检查：`connections.json` 权限非 600 时发出警告通知
- 导出包含密码时，文件必须加密（AES-256）
- 导入时检测同名连接冲突，提供覆盖/跳过/重命名选项
- 首次使用时自动创建 `~/.sql-all-in-one/` 目录和默认配置文件

#### 5.2.6 错误处理

- 配置文件不存在：创建默认文件
- 配置文件格式错误：提示用户，不崩溃，返回空列表
- 文件读写权限错误：提示用户检查权限
- SecretStorage 不可用：降级为内存存储，提示用户

#### 5.2.7 导入导出冲突处理

导入连接配置时检测冲突策略：

| 冲突类型 | 检测条件 | 处理选项 |
|---------|---------|---------|
| 同名连接 | `name` 相同 | 覆盖 / 跳过 / 自动重命名（添加 `_imported` 后缀） |
| 同 host+port+database | 连接目标相同 | 提示用户确认，标注为"疑似重复" |

### 5.3 验收标准

- [ ] 首次使用时自动创建目录和默认配置文件
- [ ] 添加/删除/更新连接后文件自动保存

## 6. P0-5：连接管理器

### 6.1 背景与问题

需要一个统一的连接管理器来管理数据库连接的完整生命周期，包括连接/断开、状态追踪、活动连接管理、自动重连。

### 6.2 功能需求

#### 6.2.1 ConnectionManager API

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `addConnection` | `config, password` | `Promise<void>` | 添加连接配置并保存密码 |
| `removeConnection` | `id` | `Promise<void>` | 断开连接并删除配置 |
| `updateConnection` | `id, config` | `Promise<void>` | 更新连接配置 |
| `connect` | `id` | `Promise<void>` | 建立数据库连接 |
| `disconnect` | `id` | `Promise<void>` | 断开数据库连接 |
| `disconnectAll` | 无 | `Promise<void>` | 断开所有连接 |
| `testConnection` | `id` | `Promise<TestConnectionResult>` | 测试连接是否可用 |
| `getAdapter` | `id` | `IDatabaseAdapter?` | 获取指定连接的适配器实例 |
| `getState` | `id` | `ConnectionState` | 获取连接状态 |
| `getAllConnections` | 无 | `ConnectionConfig[]` | 获取所有连接配置 |
| `getActiveConnection` | 无 | `ConnectionConfig?` | 获取当前活动连接 |
| `setActiveConnection` | `id` | `void` | 设置当前活动连接 |

#### 6.2.2 事件

| 事件名 | 触发时机 | 事件数据 |
|--------|---------|---------|
| `onDidChangeConnections` | 连接列表变更（添加/删除/更新） | `{ type: 'add' \| 'remove' \| 'update', connectionId }` |
| `onDidChangeConnectionState` | 连接状态变更 | `{ connectionId, oldState, newState }` |
| `onDidChangeActiveConnection` | 活动连接变更 | `{ oldId?, newId? }` |

#### 6.2.3 连接流程

```
connect(id):
1. 检查连接是否已存在 → 已连接则跳过
2. 从 ConnectionStore 获取配置
3. 从 SecretStorage 获取密码，注入到配置
4. 状态设为 Connecting
5. 检查 SSH 配置 → 启用则先建立 SSH 隧道
6. 通过 AdapterFactory 创建适配器实例
7. 调用 adapter.connect(config)
8. 状态设为 Connected
9. 触发 onDidChangeConnectionState 事件
10. 如果没有活动连接，自动设为活动连接
```

#### 6.2.4 自动重连策略

| 重试次数 | 间隔 | 条件 |
|---------|------|------|
| 第 1 次 | 2s | 连接意外断开（非用户主动断开） |
| 第 2 次 | 4s | 上次重试失败 |
| 第 3 次 | 8s | 上次重试失败 |
| 放弃 | — | 3 次均失败，状态设为 Error |

**不重连的错误**：
- `ER_ACCESS_DENIED_ERROR` — 认证失败
- `ER_DBACCESS_DENIED_ERROR` — 数据库权限不足
- 用户主动断开

#### 6.2.5 活动连接管理

- 同一时刻只有一个活动连接
- 活动连接用于 SQL 执行和 Schema 补全
- 设置活动连接时触发 `onDidChangeActiveConnection` 事件
- 连接断开时，如果断开的是活动连接，活动连接设为 undefined

### 6.3 验收标准

- [ ] `connect()` 创建适配器实例并建立连接池
- [ ] `disconnect()` 关闭连接池并清理资源
- [ ] 连接状态正确转换：Disconnected → Connecting → Connected / Error
- [ ] 活动连接切换时触发事件
- [ ] 连接意外断开时自动重试 3 次
- [ ] 认证失败不重试，直接标记为 Error
- [ ] `disconnectAll()` 在扩展停用时被调用
