# PRD-007: 跳转与导航增强

## 一、概述

为 SQL All in One 扩展新增四项代码导航能力，全部基于 `node-sql-parser` 的 AST 实现：

| 功能                    | VS Code 接口                     | 说明                                          |
| ----------------------- | -------------------------------- | --------------------------------------------- |
| **Go to Definition**    | `DefinitionProvider`             | 点击 CTE/别名 → 跳转到定义处                  |
| **Find All References** | `ReferenceProvider`              | 查找 CTE/别名的所有引用位置                   |
| **Rename Symbol**       | `RenameProvider`                 | 重命名 CTE/别名，自动更新所有引用             |
| **Breadcrumb 导航**     | `DocumentSymbolProvider`（增强） | 编辑器顶部显示 SELECT > FROM > WHERE 层级路径 |

---

## 二、设计原则

| 原则             | 说明                                                               |
| ---------------- | ------------------------------------------------------------------ |
| **AST 驱动**     | 所有符号定位基于 `node-sql-parser` AST 遍历，不使用正则            |
| **共享引擎**     | 引入 `AstNavigator` 共享导航引擎，四个 Provider 复用同一套符号索引 |
| **一致注册模式** | 遵循现有 Provider 注册方式，为 8 种 SQL 方言分别注册               |
| **向后兼容**     | 新增 `enableNavigation` 配置项，默认开启                           |
| **零误报**       | AST 天然排除注释/字符串中的关键字，不受嵌套结构干扰                |

## 四、核心引擎：AstNavigator

### 4.1 符号索引

```typescript
interface SymbolIndex {
    cteDefinitions: Map<string, vscode.Location>;
    tableAliasDefinitions: Map<string, vscode.Location>;
    columnAliasDefinitions: Map<string, vscode.Location>;
}

interface SymbolReference {
    location: vscode.Location;
    context: string; // 引用上下文描述，如 'FROM 子句'、'WHERE 条件'
}
```

### 4.2 索引构建

遍历一次 AST，收集所有定义：

```typescript
function buildIndex(ast: ASTNode, document: vscode.TextDocument): SymbolIndex {
    const index = {
        cteDefinitions: new Map(),
        tableAliasDefinitions: new Map(),
        columnAliasDefinitions: new Map(),
    };

    // 1. CTE 定义：扫描 WITH 子句
    walkAst(ast, (node) => {
        if (node.type === "with") {
            for (const item of node.value || []) {
                const name = extractName(item.name);
                const loc = toVscodeLocation(item, document);
                index.cteDefinitions.set(name.toLowerCase(), loc);
            }
        }
    });

    // 2. 表别名定义：扫描 FROM/JOIN item.as
    walkAst(ast, (node) => {
        if (node.type === "select") {
            for (const item of node.from || []) {
                if (item.as) {
                    const name = extractName(item.as);
                    const loc = toVscodeLocation(item, document);
                    index.tableAliasDefinitions.set(name.toLowerCase(), loc);
                }
                // 递归处理 JOIN 中的别名
                walkJoinAliases(item.join, index.tableAliasDefinitions, document);
            }
        }
    });

    // 3. 列别名定义：扫描 SELECT columns 的 col.as
    walkAst(ast, (node) => {
        if (node.type === "select" && Array.isArray(node.columns)) {
            for (const col of node.columns) {
                if (col.as) {
                    const name = extractName(col.as);
                    const loc = toVscodeLocation(col, document);
                    index.columnAliasDefinitions.set(name.toLowerCase(), loc);
                }
            }
        }
    });

    return index;
}
```

### 4.3 引用查找

遍历 AST，查找与目标符号名匹配的引用：

```typescript
function findReferences(
    ast: ASTNode,
    symbolName: string,
    document: vscode.TextDocument,
    symbolType: "cte" | "tableAlias" | "columnAlias",
): SymbolReference[] {
    const refs: SymbolReference[] = [];
    const nameLower = symbolName.toLowerCase();

    walkAst(ast, (node) => {
        switch (symbolType) {
            case "cte":
                // CTE 引用：FROM/JOIN 中的表名匹配
                if (isTableRef(node) && matchesName(node.table, nameLower)) {
                    refs.push({ location: toVscodeLocation(node, document), context: "FROM 引用" });
                }
                break;
            case "tableAlias":
                // 表别名引用：column_ref.table 字段匹配
                if (node.type === "column_ref" && node.table && matchesName(node.table, nameLower)) {
                    refs.push({ location: toVscodeLocation(node, document), context: "列引用" });
                }
                break;
            case "columnAlias":
                // 列别名引用：HAVING/ORDER BY 中的列名匹配
                if (isColumnRefInClause(node, ["having", "orderby"]) && matchesName(node.column, nameLower)) {
                    refs.push({ location: toVscodeLocation(node, document), context: "子句引用" });
                }
                break;
        }
    });

    return refs;
}
```

### 4.4 astify 缓存

为避免每次光标移动都重新解析 SQL（特别是 Breadcrumb 高频触发），引入解析缓存：

```typescript
class AstNavigator {
    private cache: Map<string, { version: number; ast: ASTNode; index: SymbolIndex }> = new Map();

    getAST(document: vscode.TextDocument): { ast: ASTNode; index: SymbolIndex } {
        const key = document.uri.toString();
        const cached = this.cache.get(key);
        if (cached && cached.version === document.version) {
            return { ast: cached.ast, index: cached.index };
        }
        const ast = parserEngine.astify(document.getText(), getDialect(document));
        const index = buildIndex(ast, document);
        this.cache.set(key, { version: document.version, ast, index });
        return { ast, index };
    }

    invalidate(document: vscode.TextDocument): void {
        this.cache.delete(document.uri.toString());
    }
}
```

## 五、Go to Definition

### 5.1 匹配逻辑

```
光标位置 → 提取单词 → 查找符号索引 → 返回定义位置
              │
              ├── CTE 名称？ → CTE 索引（WITH 子句中）
              ├── 表别名？   → 表别名索引（FROM/JOIN as 处）
              └── 列别名？   → 列别名索引（SELECT as 处）
```

### 5.2 实现

```typescript
class SqlDefinitionProvider implements vscode.DefinitionProvider {
    provideDefinition(document, position): vscode.Definition | null {
        const word = getWordAtPosition(document, position);
        const { index } = this.navigator.getAST(document);

        const loc =
            index.cteDefinitions.get(word.toLowerCase()) ||
            index.tableAliasDefinitions.get(word.toLowerCase()) ||
            index.columnAliasDefinitions.get(word.toLowerCase());

        return loc || null;
    }
}
```

### 5.3 示例效果

```
WITH
  orders AS (                    ← 定义处：CTE 名称
SELECT o.id
FROM orders o                    ← 点击此处 "orders" → 跳转到第2行

FROM users u                     ← 别名定义处
WHERE u.id = 1                   ← 点击 "u" → 跳转到 FROM users u
```

## 六、Find All References

### 6.1 匹配逻辑

```
光标位置 → 确定符号类型 → 遍历 AST 查找引用 → 返回 Location 列表
```

### 6.2 实现

```typescript
class SqlReferenceProvider implements vscode.ReferenceProvider {
    provideReferences(document, position, context): vscode.Location[] | null {
        const word = getWordAtPosition(document, position);
        const { ast, index } = this.navigator.getAST(document);

        const symbolType = this.detectSymbolType(word, index);
        if (!symbolType) return null;

        const refs = this.navigator.findReferences(ast, word, document, symbolType);
        return refs.map((r) => r.location);
    }
}
```

### 6.3 示例效果

```
WITH orders AS (                 ← Shift+F12 在此 → 结果面板：
    SELECT * FROM raw
)
SELECT o.id
FROM orders o                    ← 引用1：FROM orders
JOIN orders o2                   ← 引用2：FROM orders (第二个引用)
WHERE o.date > '2024-01-01'
```

### 6.4 引用上下文

每次引用附带上下文标签，在 VS Code 引用面板中展示：

| 符号类型   | 上下文标签                           |
| ---------- | ------------------------------------ |
| CTE 引用   | `FROM 子句`、`JOIN 子句`             |
| 表别名引用 | `WHERE 条件`、`SELECT 列`、`ON 条件` |
| 列别名引用 | `ORDER BY`、`HAVING`、`GROUP BY`     |

## 七、Rename Symbol

### 7.1 核心流程

```
用户按 F2 → 输入新名称 → 校验 → 构建 WorkspaceEdit → 预览 → 确认 → 批量替换
```

### 7.2 实现

```typescript
class SqlRenameProvider implements vscode.RenameProvider {
    prepareRename(document, position): vscode.Range | null {
        const word = getWordAtPosition(document, position);
        const { index } = this.navigator.getAST(document);
        return this.hasDefinition(word, index) ? document.getWordRangeAtPosition(position) : null;
    }

    provideRenameEdits(document, position, newName): vscode.WorkspaceEdit | null {
        const word = getWordText(document, position);
        const { ast, index } = this.navigator.getAST(document);

        const symbolType = this.detectSymbolType(word, index);
        if (!symbolType) return null;

        // 校验
        const validationError = this.validateNewName(newName, word, index, document);
        if (validationError) throw new Error(validationError);

        const defLocation = this.getDefinition(word, index);
        const refs = this.navigator.findReferences(ast, word, document, symbolType);

        const edit = new vscode.WorkspaceEdit();
        edit.replace(document.uri, defLocation.range, newName);
        for (const ref of refs) {
            edit.replace(document.uri, ref.location.range, newName);
        }
        return edit;
    }
}
```

### 7.3 校验规则

| 检查项     | 条件                          | 错误信息                              |
| ---------- | ----------------------------- | ------------------------------------- |
| 保留字冲突 | `newName` 是 SQL 保留字       | `'xxx' 是 SQL 保留字，不能用作标识符` |
| 名称冲突   | `newName` 与已有 CTE/别名相同 | `名称 'xxx' 已被使用`                 |
| 格式非法   | 含特殊字符或空格              | `名称只能包含字母、数字和下划线`      |
| 名称不变   | `newName === oldName`         | 不触发重命名                          |

### 7.4 示例效果

```
WITH
  user_summary AS (              ← F2 重命名 user_summary → customer_summary
    SELECT user_id, SUM(amount) AS total
    FROM orders
    GROUP BY user_id
  )
SELECT *
FROM user_summary               ← 自动更新 → customer_summary
```

F2 重命名 `user_summary` → `customer_summary`，预览显示 2 处修改（定义 + 引用），确认后一次性应用。

## 八、Breadcrumb 导航

### 8.1 VS Code 面包屑原理

VS Code 面包屑由 `DocumentSymbolProvider` 返回的 `DocumentSymbol` 层级数据驱动，自动渲染在编辑器顶部。

当前 `SqlOutlineProvider` 已注册为 `DocumentSymbolProvider`，但仅返回语句级符号 + CTE 子符号。本次增强到子句级。

### 8.2 增强后的层级结构

当光标在 WHERE 子句时，面包屑显示路径：

```
📄 example.sql > 🔍 SELECT > 📦 FROM orders > 🔎 WHERE o.date > '2024'
```

### 8.3 符号层级

```
Document (根)
 ├── Statement: SELECT                          ← SymbolKind.Event
 │    ├── WITH orders, users                     ← SymbolKind.Namespace
 │    │    ├── CTE: orders                       ← SymbolKind.Constant
 │    │    └── CTE: users                        ← SymbolKind.Constant
 │    ├── SELECT (3 columns)                     ← SymbolKind.Field
 │    │    └── total (alias)                     ← SymbolKind.Field（仅别名列）
 │    ├── FROM orders o                          ← SymbolKind.Module
 │    ├── JOIN users u ON o.uid = u.id           ← SymbolKind.Module
 │    ├── WHERE o.date > '2024-01-01'            ← SymbolKind.Boolean
 │    ├── GROUP BY o.uid                         ← SymbolKind.Array
 │    ├── HAVING total > 1000                    ← SymbolKind.Boolean
 │    └── ORDER BY total DESC                    ← SymbolKind.Array
 ├── Statement: INSERT INTO ...                  ← SymbolKind.Event
 └── Statement: CREATE TABLE ...                 ← SymbolKind.Struct
```

### 8.4 设计决策

| 决策     | 选择                      | 理由                                           |
| -------- | ------------------------- | ---------------------------------------------- |
| 列级符号 | 仅别名列展示              | 避免无别名列爆炸（SELECT 50 列 → 50 个子符号） |
| 子句标签 | 截取前 30 字符            | 避免面包屑路径过长                             |
| 多语句   | 每条语句为顶层            | 文档级面包屑天然支持                           |
| 复用大纲 | 增强 `SqlOutlineProvider` | 一份实现同时驱动大纲和面包屑                   |

### 8.5 实现要点

在现有 `SqlOutlineProvider.processSelectStatement()` 方法中增加子句级 `DocumentSymbol`：

```typescript
private processSelectStatement(doc, node): vscode.DocumentSymbol {
    const children: vscode.DocumentSymbol[] = [];

    // 已有：WITH clause
    if (node.with) children.push(...this.processWithClause(doc, node.with));

    // 新增：SELECT 列（仅别名）
    if (node.columns) children.push(this.processSelectColumns(doc, node.columns));

    // 新增：FROM + JOIN
    if (node.from) children.push(...this.processFromClauses(doc, node.from));

    // 新增：WHERE / GROUP BY / HAVING / ORDER BY
    if (node.where)  children.push(this.createClauseSymbol(doc, node.where, 'WHERE'));
    if (node.groupby) children.push(this.createClauseSymbol(doc, node.groupby, 'GROUP BY'));
    if (node.having)  children.push(this.createClauseSymbol(doc, node.having, 'HAVING'));
    if (node.orderby) children.push(this.createClauseSymbol(doc, node.orderby, 'ORDER BY'));

    return new vscode.DocumentSymbol(
        this.getStatementLabel(node),
        this.getStatementDetail(node),
        SymbolKind.Event,
        range, selectionRange,
        children
    );
}
```

## 十一、性能设计

| 策略                | 说明                                                           |
| ------------------- | -------------------------------------------------------------- |
| **解析缓存**        | 以 `{uri}#{version}` 为键缓存 AST + 索引，文档未变更时直接复用 |
| **索引预构建**      | 解析时同步构建符号索引，之后通过 Map 实现 O(1) 查找            |
| **增量失效**        | `onDidChangeTextDocument` 事件触发缓存失效                     |
| **Breadcrumb 去抖** | 光标移动高频触发，使用 AST 缓存避免重复解析                    |
| **提前短路**        | `enableNavigation: false` 时所有 Provider 直接返回 null        |

## 十二、已知局限

| 局限           | 说明                                                                   | 缓解措施                                      |
| -------------- | ---------------------------------------------------------------------- | --------------------------------------------- |
| CTE 与表名冲突 | 无法区分 `FROM orders` 中的 orders 是 CTE 还是物理表                   | CTE 优先匹配，同时在引用面板中标注 `CTE 引用` |
| 列别名弱绑定   | HAVING/ORDER BY 中的列名与 SELECT 列别名只是同名匹配，不是真正语义绑定 | 引用面板标注 `可能引用`                       |
| 单文件范围     | 跳转和引用仅限于当前文档，不跨文件                                     | 未来可扩展到 workspace 范围                   |
| 字符串内引用   | `EXECUTE IMMEDIATE 'SELECT * FROM cte_name'` 中的引用不被识别          | AST 不处理字符串内容，属于合理限制            |
