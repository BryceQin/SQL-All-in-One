## 2. P0-1：SQL 感知的智能注释切换

### 2.1 背景与问题

VSCode 内置的 `Cmd+/`（Toggle Line Comment）对所有语言一视同仁：选中多行就在每行前面加 `//` 或 `--`。但在 SQL 场景下，用户有更丰富的注释需求：

- 选中多行代码块 → 希望用 `/* */` 包裹，而不是每行加 `--`
- 在 DDL 的列定义行 → 希望快速生成 `COMMENT ''` 列注释
- 选中的是一个完整 SQL 语句 → 希望用 `/* sql-formatter-disable */` 禁用格式化（而非注释掉）

### 2.2 功能需求

#### 2.2.1 三种注释模式

插件需要覆盖 VSCode 默认的注释切换行为，根据**当前选中内容的上下文**智能选择注释方式：

| 上下文判断                   | 触发快捷键    | 行为                                                                 |
| ---------------------------- | ------------- | -------------------------------------------------------------------- |
| 光标在**任意位置**（未选中） | `Cmd+/`       | 切换当前行 `--` 注释（保持 VSCode 默认行为）                         |
| 选中**单行部分文本**         | `Cmd+/`       | 切换当前行 `--` 注释（保持 VSCode 默认行为）                         |
| 选中**跨多行文本**           | `Cmd+/`       | 用 `/* */` 包裹选中内容（而非逐行加 `--`）                           |
| 选中**完整 SQL 语句**        | `Cmd+Shift+/` | 用 `/* sql-formatter-disable */` / `/* sql-formatter-enable */` 包裹 |
| 光标在 DDL **列定义行**      | `Cmd+Shift+/` | 在该列定义末尾添加 `COMMENT ''`，光标定位到引号内                    |

#### 2.2.2 多行块注释切换详细行为

```
操作前（选中3行）：
    SELECT a, b
    FROM t1
    WHERE c > 10

第一次 Cmd+/ → 添加块注释：
    /* SELECT a, b
       FROM t1
       WHERE c > 10 */

第二次 Cmd+/ → 移除块注释（恢复原状）：
    SELECT a, b
    FROM t1
    WHERE c > 10
```

**边界情况**：

- 如果选中的内容已经被 `/* */` 包裹 → `Cmd+/` 移除块注释
- 如果选中的内容部分被 `/* */` 包裹（嵌套场景）→ 不做处理，提示用户
- 如果选中内容包含 `*/` 字符串（如字符串字面量）→ 仍然包裹，但提示可能有问题

#### 2.2.3 DDL 列注释快速生成

```
操作前（光标在列定义行任意位置）：
    user_name STRING,
    user_age INT

操作：光标放在 user_age 那一行 → Cmd+Shift+/

操作后：
    user_name STRING,
    user_age INT COMMENT '',  -- 光标定位在引号内
```

**智能定位**：

- 如果列定义后已有逗号 → COMMENT 插入在逗号之前
- 如果列定义后没有逗号（最后一列）→ COMMENT 追加在末尾
- 如果该列已有 COMMENT → 光标跳转到已有 COMMENT 的引号内（不重复添加）

#### 2.2.4 格式化禁用包裹

```
操作前（选中完整查询）：
    SELECT /* 不想被格式化的复杂计算 */
           a * 0.05 + b * 0.1 + c * 0.2
    FROM t1

操作：Cmd+Shift+/

操作后：
    /* sql-formatter-disable */
    SELECT /* 不想被格式化的复杂计算 */
           a * 0.05 + b * 0.1 + c * 0.2
    FROM t1
    /* sql-formatter-enable */
```

**智能判断"完整 SQL 语句"**：

- 选中内容以 `SELECT`/`INSERT`/`UPDATE`/`DELETE`/`CREATE`/`WITH` 开头
- 选中内容以 `;` 结尾（或到文件末尾）
- 如果选中的只是一段表达式或子查询 → 不触发此模式，回退到普通块注释

### 2.3 交互设计

#### 2.3.1 快捷键绑定

| 快捷键                                            | 命令 ID                                | 说明                                     |
| ------------------------------------------------- | -------------------------------------- | ---------------------------------------- |
| `Cmd+/`（macOS）/ `Ctrl+/`（Windows）             | `sql-all-in-one.toggleComment`         | SQL 智能注释切换（覆盖 VSCode 默认）     |
| `Cmd+Shift+/`（macOS）/ `Ctrl+Shift+/`（Windows） | `sql-all-in-one.toggleAdvancedComment` | 高级注释（DDL COMMENT / 格式化禁用包裹） |

**与 VSCode 默认行为的兼容**：

- 插件注册 `sql-all-in-one.toggleComment` 命令并绑定 `Cmd+/`
- 仅在 `sql` / `hive` 语言文件中激活
- 在其他语言文件中保持 VSCode 默认的 `editor.action.commentLine`
- 提供配置项 `enableSmartCommentToggle`（默认 `true`），关闭后回退到 VSCode 默认行为

#### 2.3.2 右键菜单

在 SQL 文件的右键菜单中新增：

```
📝 Comment
   ├── Toggle Line Comment          Cmd+/
   ├── Toggle Block Comment         Cmd+Shift+/
   ├── Add Column COMMENT           Cmd+Shift+/
   └── Wrap with Formatter Disable  Cmd+Shift+/
```

#### 2.3.3 状态栏提示

当执行智能注释操作后，状态栏短暂显示操作结果（2 秒）：

- "已添加块注释"
- "已移除块注释"
- "已添加 DDL 列注释"
- "已添加格式化禁用标记"

### 2.4 实现要点

| 要点       | 说明                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| 上下文判断 | 利用现有 AST 解析结果判断光标所在节点类型（SELECT 语句、列定义、表达式等） |
| 缩进保持   | 添加块注释时保持内部代码的原始缩进                                         |
| 撤销支持   | 所有操作作为一个原子编辑，支持 `Cmd+Z` 一步撤销                            |
| 多选区     | 支持 VSCode 的多光标/多选区场景                                            |
| 性能       | 只在用户主动触发时运行，不增加后台开销                                     |

## 3. P0-2：注释模板补全系统

### 3.1 背景与问题

当前插件只有 1 个 `comment` Snippet（文件头注释），用户在编写 SQL 时经常需要手写各种注释，效率低、格式不统一。

### 3.2 新增 Snippet 定义

#### 3.2.1 全部新增 Snippet 一览

| 前缀      | 触发场景            | 生成的注释模板                 |
| --------- | ------------------- | ------------------------------ |
| `header`  | 文件最顶部（第1行） | 文件头注释（自动识别上游依赖） |
| `todo`    | 任意位置            | 带责任人和日期的 TODO          |
| `fixme`   | 任意位置            | FIXME 标记                     |
| `hack`    | 任意位置            | HACK 临时方案标记              |
| `desc`    | SELECT 语句上方     | 查询说明注释块                 |
| `col`     | DDL 列定义行        | 列 COMMENT 注释                |
| `tbl`     | CREATE TABLE 上方   | 表 COMMENT 注释                |
| `section` | 任意位置            | 分区标题注释                   |

#### 3.2.2 详细模板定义

**3.2.2.1 `header` -- 文件头注释（自动识别上游依赖）**

```
前缀：header
触发条件：光标在文件第1行（或前3行内），文件内容非空

生成内容：
-- ============================================================
-- 脚本名称：${1:script_name}
-- 功能描述：${2:description}
-- 作者：${3:author}
-- 创建时间：${4:create_date}
-- ============================================================
-- 修改记录：
--   日期         修改人       修改内容
--   ${5:modify_date}  ${6:modifier}     ${7:modify_content}
-- ============================================================
-- 上游依赖：
--   输入表：
--     - ${8:table_1}
--     - ${9:table_2}
--   输出表：
--     - ${10:output_table}
-- ============================================================
$0

自动填充变量（无需用户输入）：
  ${1:script_name}   -- 当前文件名（如 dim_user_etl.sql → dim_user_etl）
  ${3:author}         -- 取配置项 headerAuthor 的值，为空则留空等待用户输入
  ${4:create_date}    -- 如果文件已有文件头注释且含创建时间 → 保留原值不变
                      -- 如果文件无文件头或创建时间为空 → 自动填当天日期（YYYY-MM-DD）
  ${5:modify_date}    -- 始终自动填当天日期（YYYY-MM-DD）
  ${6:modifier}       -- 取配置项 headerModifier 的值，为空则回退取 headerAuthor 的值

自动识别填充变量（核心功能）：
  ${8:table_1} ... ${N:table_N}
    -- 通过扫描文件中所有 FROM / JOIN / INSERT INTO / INSERT OVERWRITE TABLE
    -- 自动提取所有引用的表名（含库名前缀如 ods.user_info）
    -- 去重后按字母序排列
    -- 每个表生成一个独立的占位行，供用户确认和补充

手动输入变量：
  ${2:description}     -- 脚本功能描述
  ${7:modify_content}   -- 本次修改内容
  ${10:output_table}    -- 输出目标表（默认从 INSERT INTO/OVERWRITE 中提取）

示例输出（假设文件名为 dim_user_etl.sql）：
-- ============================================================
-- 脚本名称：dim_user_etl
-- 功能描述：用户维度表每日ETL加工
-- 作者：zhangsan
-- 创建时间：2026-05-19
-- ============================================================
-- 修改记录：
--   日期         修改人       修改内容
--   2026-05-19  zhangsan     初始版本
-- ============================================================
-- 上游依赖：
--   输入表：
--     - ods.order_info          ← 自动识别
--     - ods.user_base           ← 自动识别
--     - ods.user_behavior_log   ← 自动识别
--   输出表：
--     - dim.dim_user             ← 自动识别（从 INSERT INTO 提取）
-- ============================================================
```

**上游依赖自动识别逻辑**：

```
识别范围：
  1. FROM 子句中的表名（含子查询别名后的原始表）
     SELECT ... FROM db.table1 t1 JOIN db.table2 t2 ON ...
     → 提取: db.table1, db.table2

  2. JOIN 系列子句中的表名
     LEFT JOIN / RIGHT JOIN / INNER JOIN / FULL JOIN / CROSS JOIN
     → 提取: 各 JOIN 后的表名

  3. INSERT 目标表
     INSERT INTO db.target_table / INSERT OVERWRITE TABLE db.target_table
     → 提取到【输出表】

  4. CREATE TABLE ... AS SELECT 中的源表
     → FROM 部分提取到【输入表】，CREATE 的表提取到【输出表】

  5. UNION ALL / UNION 各分支中的 FROM 表
     → 全部提取

  6. WITH (CTE) 子句内部的 FROM 表
     → 提取 CTE 定义中引用的实际表，不包含 CTE 名称本身

  7. 子查询内部的 FROM 表
     SELECT ... FROM (SELECT ... FROM t1) sub JOIN t2
     → 提取: t1, t2（穿透子查询）

去重与格式化：
  - 所有表名去重（忽略大小写差异）
  - 保留库名前缀（如 ods.table_name）
  - 按字母序排列
  - 每个表占一行，格式：--     - db.table_name

边界处理：
  - 文件中的字符串字面量（如 'FROM 2020-01-01'）不参与识别
  - SQL 注释内的表名不参与识别
  - 如果文件无任何表引用 → 上游依赖区域仍然生成，但显示 "（未检测到表依赖，请手动填写）"
  - 如果表数量超过 20 个 → 只列出前 20 个 + "（共 N 个表，此处仅展示前20个）"
```

**与现有 `comment` Snippet 的关系**：

- 现有 `comment` Snippet（前缀 `comment`）保持不变，适用于文件中间位置或简单场景
- 新增 `header` Snippet（前缀 `header`）定位为**文件顶部专用**，功能更完整
- 用户可根据场景选择：简单头部用 `comment`，完整头部用 `header`

**3.2.2.2 `todo` -- TODO 注释**

```
前缀：todo
触发条件：光标在 SQL 文件中任意位置（非字符串内）

生成内容：
-- TODO(${1:username}): ${2:description}

变量：
  ${1:username}  -- 从配置项 headerAuthor 读取，为空则显示 "username"
  ${2:description}  -- 选中状态，用户直接输入

示例输出：
-- TODO(zhangsan): 优化此子查询，考虑使用窗口函数替代
```

**3.2.2.3 `fixme` -- FIXME 注释**

```
前缀：fixme
触发条件：光标在 SQL 文件中任意位置

生成内容：
-- FIXME: ${1:description}
-- Reason: ${2:why this needs fixing}

变量：
  ${1:description}  -- 问题描述
  ${2:why this needs fixing}  -- 原因说明

示例输出：
-- FIXME: LEFT JOIN 可能导致右侧数据丢失
-- Reason: 产品要求保留所有左侧用户数据
```

**3.2.2.4 `hack` -- HACK 临时方案注释**

```
前缀：hack
触发条件：光标在 SQL 文件中任意位置

生成内容：
-- HACK: ${1:description}
-- TODO: ${2:proper solution}

变量：
  ${1:description}  -- 临时方案描述
  ${2:proper solution}  -- 正确方案

示例输出：
-- HACK: 用 UNION ALL 模拟 FULL OUTER JOIN（Hive 不支持）
-- TODO: 升级到 Hive 3.0 后改用 FULL OUTER JOIN
```

**3.2.2.5 `desc` -- 查询说明注释**

```
前缀：desc
触发条件：光标在 SELECT / INSERT / WITH 语句上方空行

生成内容：
-- ============================================
-- 查询说明：${1:功能描述}
-- 涉及表：${2:table_list}
-- 条件：${3:filter_conditions}
-- 输出：${4:output_description}
-- 作者：${5:$CURRENT_USER}
-- 日期：$CURRENT_YEAR-$CURRENT_MONTH-$CURRENT_DATE
-- ============================================

变量：
  ${1:功能描述}
  ${2:table_list}
  ${3:filter_conditions}
  ${4:output_description}
  ${5:$CURRENT_USER}  -- 从配置项 headerAuthor 读取
  $CURRENT_YEAR / $CURRENT_MONTH / $CURRENT_DATE  -- 自动填充

示例输出：
-- ============================================
-- 查询说明：获取活跃用户的近30天订单汇总
-- 涉及表：users, orders, order_items
-- 条件：用户状态=active, 订单时间>=30天前, 订单状态=已完成
-- 输出：用户名、订单数、总金额
-- 作者：zhangsan
-- 日期：2026-05-19
-- ============================================
SELECT u.name, COUNT(o.id) AS order_cnt, SUM(o.amount) AS total
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE u.status = 'active'
  AND o.created_at >= DATE_SUB(CURRENT_DATE, 30)
  AND o.status = 'completed'
GROUP BY u.name
```

**3.2.2.6 `col` -- DDL 列注释**

```
前缀：col
触发条件：光标在 DDL 列定义行（紧跟在数据类型后面或逗号后面）

生成内容：
COMMENT '${1:列说明}'

示例操作（光标在 INT 后面）：
修改前：
    user_age INT,

输入 col → 补全后：
    user_age INT COMMENT '列说明',    -- 光标选中"列说明"三个字

变量：
  ${1:列说明}  -- 默认占位文本，选中状态
```

**智能定位**：

- 如果该行已有逗号 → COMMENT 插入在逗号之前
- 如果该行没有逗号（最后一列）→ COMMENT 追加后不加逗号
- 如果该行已有 COMMENT → 不重复添加，直接选中已有 COMMENT 的文本内容

**3.2.2.7 `tbl` -- 表 COMMENT 注释**

```
前缀：tbl
触发条件：光标在 CREATE TABLE 语句的最后（右括号后面）

生成内容：
COMMENT '${1:表说明}'

示例（光标在 ) 后面）：
CREATE TABLE dim_user (
    user_id BIGINT,
    user_name STRING
) COMMENT '用户维度表'    -- 光标选中"用户维度表"
```

**3.2.2.8 `section` -- 分区标题注释**

```
前缀：section
触发条件：光标在 SQL 文件中任意位置

生成内容：
-- ============================================================
-- ${1:section_title}
-- ============================================================

变量：
  ${1:section_title} -- 分区标题

示例输出：
-- ============================================================

-- ============================================================
```

### 3.4 与现有 Snippet 的关系

- 现有 `comment` Snippet（文件头注释）保持不变
- 新 Snippet 统一注册在 `sql` 和 `hive` 语言下
- 当 `enableSnippets` 为 `false` 时，新旧 Snippet 全部禁用

### 3.5 实现要点

| 要点             | 说明                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 注册方式         | 静态 Snippet（todo/fixme/hack/desc/section）统一在 `snippets/sql.json` 中追加，复用现有 Snippet 框架                                         |
| 动态 Snippet     | `header`、`col`、`tbl` 需要通过 `CompletionItemProvider` 实现，根据上下文动态调整插入内容                                                    |
| 上游依赖识别     | `header` Snippet 生成前，使用轻量正则扫描 或 复用现有 Tokenizer 遍历 Token 流，提取 FROM/JOIN/INSERT 中的表名；不依赖完整 AST 解析以保持性能 |
| 作者/修改人      | 从配置项 `headerAuthor` / `headerModifier` 读取，不再依赖 git config                                                                         |
| 创建时间智能保留 | 如果文件已有文件头注释且含日期 → 原样保留；否则自动填当天日期                                                                                |
| col/tbl 智能定位 | 需要使用 `CompletionItemProvider` 而非纯 Snippet，以便根据上下文动态调整插入位置                                                             |
| 兼容性           | 纯文本 Snippet 回退到 VSCode 原生支持，动态 Snippet 通过 `CompletionItemProvider` + `SnippetString` 实现                                     |

## 4. P0-3：注释校验 Lint 规则

### 4.1 背景与问题

当前插件的 14 条 Lint 规则全部聚焦于 SQL 语法和代码质量，没有关于注释的规则。在实际工程中，注释缺失/过期/不规范是常见的代码质量问题。

### 4.2 新增 Lint 规则

#### 4.2.1 规则总览

| 规则 ID                  | 名称                   | 默认严重级别 | 默认启用 |
| ------------------------ | ---------------------- | ------------ | -------- |
| `missing_query_comment`  | 复杂查询缺少说明注释   | warning      | true     |
| `missing_column_comment` | DDL 列定义缺少 COMMENT | warning      | true     |
| `commented_out_code`     | 疑似注释掉的大段代码   | info         | true     |
| `expired_todo`           | 过期的 TODO/FIXME 标记 | info         | true     |

#### 4.2.2 规则详细设计

---

**规则 1：`missing_query_comment` -- 复杂查询缺少说明注释**

```
ID: missing_query_comment
严重级别: warning（可配置为 error / warning / info / off）
默认状态: 启用

触发条件：
  一个 SELECT 语句同时满足以下条件时，如果该语句上方没有注释，则报告：
  - 总行数 >= N（默认 20 行，可通过 threshold_line_count 配置）
  - 或 JOIN 数量 >= M（默认 3 个，可通过 threshold_join_count 配置）
  - 或 子查询数量 >= K（默认 2 个，可通过 threshold_subquery_count 配置）

忽略条件：
  - SELECT 语句上方 3 行内有任何注释（行注释或块注释）
  - SELECT 语句在 CREATE TABLE AS / INSERT INTO 内部且外层已有注释
  - 文件总行数 < 20（小文件不强制）

报告信息：
  Message: "复杂查询（{N}行/{M}个JOIN/{K}个子查询）缺少说明注释，建议添加查询功能描述"
  Severity: Warning
  Code Action: "添加查询说明注释" → 插入 desc Snippet 模板

示例：
  ✓ 无注释 + 5行 SELECT + 1个 JOIN → 不触发
  ✓ 有注释 + 50行 SELECT + 5个 JOIN → 不触发
  ✗ 无注释 + 30行 SELECT + 4个 JOIN → 触发 Warning
```

---

**规则 2：`missing_column_comment` -- DDL 列定义缺少 COMMENT**

```
ID: missing_column_comment
严重级别: warning（可配置为 error / warning / info / off）
默认状态: 启用

触发条件：
  CREATE TABLE 语句中的列定义（非主键、非分区键等特殊列）没有 COMMENT 子句

忽略条件：
  - 主键列（PRIMARY KEY 修饰的列）
  - 分区列（PARTITIONED BY 中的列）
  - 临时表（CREATE TEMPORARY TABLE）
  - 外部表可通过配置项 external_table_exempt 跳过

报告信息：
  Message: "列 '{column_name}' 缺少 COMMENT 注释"
  Severity: Warning
  Code Action: "添加 COMMENT 占位符" → 追加 `COMMENT ''` 并定位光标

聚合行为：
  - 同一 DDL 中多个缺失 COMMENT 的列聚合成一条诊断：
    "CREATE TABLE 中有 {N} 个列缺少 COMMENT 注释"
  - 聚合模式下 Code Action 变为："为所有缺失列添加 COMMENT"
  - 可通过配置项 aggregate_missing_comments 控制（默认 true）

示例：
  CREATE TABLE t1 (
      id BIGINT,          -- ✗ Warning
      name STRING,        -- ✗ Warning
      age INT COMMENT '', -- ✓ 有占位符，不触发
      dt STRING           -- ✗ 如果是分区列则忽略
  )
```

**规则 3：`commented_out_code` -- 疑似注释掉的大段代码**

```
ID: commented_out_code
严重级别: info（可配置为 error / warning / info / off）
默认状态: 启用

触发条件：
  使用 /* */ 或 连续 -- 注释掉的内容看起来像 SQL 代码（包含 SELECT/FROM/WHERE/JOIN 等 SQL 关键字）

判断依据：
  - 块注释内容包含的 SQL 关键字 >= 3 个（SELECT, FROM, WHERE, JOIN, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, GROUP BY, ORDER BY, HAVING, UNION）
  - 或连续行注释（>= 3 行），每行都看起来像 SQL 片段
  - 且块注释内容超过 N 行（默认 3 行，可配置）

忽略条件：
  - 注释中包含 `sql-formatter-disable` / `sql-formatter-enable`
  - 注释中 SQL 关键字以文档形式出现（如 "SELECT 语句用于..." 这种讲解型文字）
  - 注释开头有 `-- 示例`、`-- Example`、`-- 说明`、`-- Description` 等文档标记

报告信息：
  Message: "发现注释掉的代码（{N}行），建议确认后删除或取消注释"
  Severity: Info
  Code Action:
    - "取消注释" → 移除注释符号，恢复代码
    - "删除注释代码" → 删除整段

示例：
  ✗ 触发：
  /*
  SELECT a, b
  FROM t1
  WHERE c > 10
  */

  ✓ 不触发：
  /*
  这段查询用于获取用户数据
  SELECT 语句关联了 users 和 orders 表
  */
```

**规则 4：`expired_todo` -- 过期的 TODO/FIXME 标记**

```
ID: expired_todo
严重级别: info（可配置为 error / warning / info / off）
默认状态: 启用

触发条件：
  注释中匹配 TODO/FIXME 并包含日期标记，且日期已过期

日期匹配模式（按优先级）：
  1. TODO(YYYY-MM-DD): ...       （显式日期格式）
  2. TODO(YYYY/MM/DD): ...
  3. TODO(username, YYYY-MM-DD): ...
  4. TODO vX.Y: ...              （版本号，依赖项目版本配置比对）
  5. @deadline YYYY-MM-DD        （在注释正文中出现）

过期判定：
  - 日期 < 当前日期 → expired
  - 可配置 grace_period_days（默认 7 天宽限期）

报告信息：
  Message: "TODO 标记已过期（{date}），已超期 {N} 天，请确认是否仍需处理"
  Severity: Info
  Code Action:
    - "标记为已完成" → 将 TODO 改为 DONE
    - "更新日期" → 将日期更新为今天
    - "移除标记" → 删除整行注释

示例：
  ✓ 未过期：
  -- TODO(2026-06-01): 优化此查询 → 不触发（未来日期）

  ✗ 已过期：
  -- TODO(2025-12-31): 迁移到新表 → 触发 Info（已过期 139 天）

  ✓ 宽限期内：
  -- TODO(2026-05-15): 修复空值问题 → 当前 2026-05-19，已过期 4 天，在 7 天宽限期内，不触发
```

## 6. 验收标准

### 6.1 P0-1 智能注释切换

- [ ] 打开 `.sql` 文件，选中多行 SQL 代码，按 `Cmd+/`，选中的代码被 `/* */` 包裹
- [ ] 再次按 `Cmd+/`，块注释被移除，代码恢复原状
- [ ] 在 DDL 列定义行按 `Cmd+Shift+/`，自动添加 `COMMENT ''` 且光标在引号内
- [ ] 该列已有 COMMENT 时，按 `Cmd+Shift+/` 光标跳到已有 COMMENT 引号内
- [ ] 选中完整 SELECT 语句按 `Cmd+Shift+/`，自动用 disable/enable 注释包裹
- [ ] 在 `.js` 文件中按 `Cmd+/`，行为回退到 VSCode 默认（不受插件影响）
- [ ] 设置 `enableSmartCommentToggle: false` 后，行为回退到 VSCode 默认
- [ ] `Cmd+Z` 可一步撤销整个注释操作

### 6.2 P0-2 注释模板补全

- [ ] 输入 `header` 触发补全，在文件顶部生成完整文件头注释（含脚本名、作者、日期）
- [ ] `header` Snippet 能正确从文件名提取 `${script_name}`
- [ ] `header` Snippet 的 `${author}` 从配置项 `headerAuthor` 读取，未配置时留空
- [ ] `header` Snippet 的 `${modifier}` 从配置项 `headerModifier` 读取，未配置时回退取 `headerAuthor`
- [ ] `header` Snippet 的 `${create_date}`：文件已有文件头且含创建时间 → 保留原值；否则自动填当天日期
- [ ] `header` Snippet 的 `${modify_date}` 始终自动填当天日期
- [ ] `header` Snippet 的【上游依赖-输入表】能自动识别 FROM/JOIN 中引用的所有表名并去重排列
- [ ] `header` Snippet 的【上游依赖-输出表】能自动识别 INSERT INTO/OVERWRITE 的目标表
- [ ] `header` Snippet 在 SQL 无任何表引用时，显示"未检测到表依赖，请手动填写"
- [ ] `header` Snippet 不会提取字符串字面量和 SQL 注释内的表名
- [ ] `header` Snippet 表数量超过 20 个时，显示前 20 个 + 总数提示
- [ ] 输入 `todo` 触发补全，生成带用户名的 TODO 注释
- [ ] 输入 `fixme` 触发补全，生成 FIXME 注释
- [ ] 输入 `hack` 触发补全，生成 HACK 注释
- [ ] 输入 `desc` 触发补全，生成完整的查询说明注释块
- [ ] 在 DDL 列定义行输入 `col`，自动在正确位置插入 `COMMENT ''`
- [ ] 在 CREATE TABLE 右括号后输入 `tbl`，生成表 COMMENT
- [ ] 输入 `section` 触发补全，生成分区标题注释
- [ ] `desc` 和 `todo` Snippet 中的用户名变量从配置项 `headerAuthor` 读取
- [ ] `$CURRENT_DATE` 变量能正确填充当天日期
- [ ] 设置 `enableSnippets: false` 时，新旧 Snippet 全部禁用

### 6.3 P0-3 注释 Lint 规则

- [ ] 打开一个超过 20 行且无注释的 SELECT 查询，出现 "缺少说明注释" Warning
- [ ] 在该查询上方添加注释后，Warning 消失
- [ ] 打开含无 COMMENT 列的 CREATE TABLE DDL，出现 "缺少 COMMENT" Warning
- [ ] 当多个列缺 COMMENT 且配置聚合模式时，只出现一条聚合 Warning
- [ ] 给缺失列添加 `COMMENT ''` 占位符后，Warning 消失
- [ ] 打开含大段注释代码（3行以上SQL关键字）的文件，出现 Info 提示
- [ ] 打开含过期 TODO（日期超过 7 天前）的文件，出现 Info 提示
- [ ] 每条 Lint 规则的 Code Action 都能正确执行
- [ ] 将规则级别设为 "off" 后，不产生诊断
- [ ] 调整阈值配置（如 threshold_line_count）后，诊断行为相应变化

## 7. 非功能需求

### 7.1 性能

- 智能注释切换：操作响应时间 < 50ms（不依赖 AST 完整重解析）
- Snippet 补全：触发延迟与 VSCode 原生 Snippet 一致（< 10ms）
- Lint 规则：不走完整 AST 解析，使用轻量正则匹配 + 行扫描，大文件（5000行）增量检测 < 200ms

### 7.2 兼容性

- 与 VSCode 内置注释切换行为向后兼容（可通过配置关闭插件覆盖）
- 与现有的 14 条 Lint 规则共存，不互相干扰
- 与 `/* sql-formatter-disable */` 机制不冲突
- 支持 VSCode >= 1.108.1（与现有保持一致）

### 7.3 国际化

- 诊断消息、Code Action 标题、状态栏提示使用中文（与现有风格一致）
- Snippet 占位文本使用中文
