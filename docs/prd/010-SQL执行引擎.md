## 1. 功能概览

实现 SQL 执行的核心引擎，包括语句识别、查询执行、安全拦截、查询历史。本迭代完成后，用户可以在编辑器中执行 SQL 并在输出通道看到结果。

| 编号 | 功能             | 一句话描述                             | 用户感知强度 |
| ---- | ---------------- | -------------------------------------- | ------------ |
| P0-1 | SQL 语句智能识别 | 基于 AST 精准识别光标所在语句          | ★★★★☆        |
| P0-2 | 查询执行器       | 支持超时、取消、事件驱动的查询执行     | ★★★★★        |
| P0-3 | 事务支持         | 事务保证原子性，支持提交和回滚         | ★★★☆☆        |
| P0-4 | 安全拦截         | 基于 AST 分析危险 SQL 并拦截确认       | ★★★☆☆        |
| P0-5 | 查询历史         | 持久化的查询历史记录，支持搜索和重执行 | ★★★☆☆        |

## 2. P0-1：SQL 语句智能识别

### 2.1 背景与问题

用户在编辑器中可能有多条 SQL 语句，需要精准识别光标所在的语句。Navicat 使用简单的分号分割，本项目可复用已有的 AST 解析能力，实现更精准的语句识别。

### 2.2 功能需求

#### 2.2.1 SqlStatementDetector API

| 方法                       | 参数                  | 返回值                | 说明                                    |
| -------------------------- | --------------------- | --------------------- | --------------------------------------- |
| `detectCurrentStatement`   | `document, position`  | `DetectedStatement`   | 识别光标所在语句                        |
| `detectSelectionOrCurrent` | `document, selection` | `DetectedStatement`   | 有选区返回选区，无选区返回当前语句      |
| `detectAllStatements`      | `document`            | `DetectedStatement[]` | 识别文档中所有语句                      |
| `parseDelimiter`           | `document`            | `string`              | 解析当前文档的分隔符（MySQL DELIMITER） |

#### 2.2.1a 批量执行策略

支持智能识别和批量执行多条SQL语句：

| 功能           | 说明                                             |
| -------------- | ------------------------------------------------ |
| 智能分隔符识别 | 支持标准分号分隔，同时识别MySQL的`DELIMITER`指令 |
| 语句边界检测   | 正确处理字符串、注释、存储过程体中的分号         |
| 逐条执行模式   | 逐条执行，失败可选择中止或继续                   |
| 事务执行模式   | 在单个事务中执行所有语句                         |
| 断点续执行     | 保存执行进度，支持从失败位置继续                 |

**批量执行配置**：

| 配置项                                  | 类型      | 默认值         | 说明                                 |
| --------------------------------------- | --------- | -------------- | ------------------------------------ |
| `sql-all-in-one.execution.batchMode`    | `enum`    | `'sequential'` | 批量执行模式：sequential/transaction |
| `sql-all-in-one.execution.onError`      | `enum`    | `'stop'`       | 错误处理：stop/continue              |
| `sql-all-in-one.execution.saveProgress` | `boolean` | `true`         | 保存执行进度                         |

#### 2.2.2 DetectedStatement 结构

| 字段    | 类型            | 说明              |
| ------- | --------------- | ----------------- |
| `sql`   | `string`        | 提取出的 SQL 文本 |
| `range` | `vscode.Range`  | 在文档中的范围    |
| `type`  | `StatementType` | 语句类型          |

#### 2.2.3 StatementType 枚举

```
'SELECT' | 'INSERT' | 'UPDATE' | 'DELETE' | 'CREATE' | 'ALTER' | 'DROP' | 'TRUNCATE' | 'RENAME'
| 'GRANT' | 'REVOKE' | 'SET' | 'SHOW' | 'USE' | 'CALL' | 'EXPLAIN' | 'OTHER'
```

#### 2.2.4 识别策略

**优先级**：

1. 有选区 → 返回选区内容
2. 无选区 → AST 解析识别当前语句
3. AST 解析失败 → 回退到分号分割

**AST 识别流程**：

1. 复用 `SqlParserEngine` 解析文档为 AST
2. 遍历 AST 节点，找到包含光标位置的语句节点
3. 提取语句文本和范围

**回退策略（分号分割）**：

1. 从文档开头扫描分号
2. 找到光标前后最近的分号
3. 提取中间的文本作为当前语句
4. 处理引号内的分号（不作为分隔符）

**分号回退的已知限制**（第一版不处理，后续迭代优化）：

- 存储过程/函数体中的分号（`BEGIN...END` 块内）会被误判为语句分隔符
- 字符串常量中的分号（如 `INSERT INTO t VALUES ('a;b')`）
- MySQL `DELIMITER` 指令改变分隔符

对于上述场景，建议用户使用选区执行（`Ctrl+Shift+R`）作为替代方案。

#### 2.2.5 边界情况

| 场景             | 行为                 |
| ---------------- | -------------------- |
| 空文档           | 返回空语句           |
| 光标在空白行     | 返回最近的上一条语句 |
| 光标在分号上     | 返回分号前的语句     |
| 多语句在同一行   | 返回光标所在语句     |
| 语句未以分号结尾 | 从语句开始到文档末尾 |

### 2.3 验收标准

- [ ] 单语句文档正确识别
- [ ] 多语句文档中光标定位到正确语句
- [ ] 有选区时返回选区内容
- [ ] 无选区时返回光标所在语句
- [ ] 带分号和不带分号的语句均可识别
- [ ] AST 解析失败时回退到分号分割

## 3. P0-2：查询执行器

### 3.1 背景与问题

需要一个支持超时、取消、事件驱动的查询执行引擎，作为 SQL 执行的核心。

### 3.2 功能需求

#### 3.2.1 QueryExecutor API

| 方法      | 参数                     | 返回值                 | 说明               |
| --------- | ------------------------ | ---------------------- | ------------------ |
| `execute` | `adapter, sql, options?` | `Promise<QueryResult>` | 执行查询           |
| `cancel`  | `queryId`                | `void`                 | 取消正在执行的查询 |

#### 3.2.2 QueryOptions

| 字段       | 类型           | 默认值  | 说明             |
| ---------- | -------------- | ------- | ---------------- |
| `maxRows`  | `number`       | `1000`  | 结果集最大行数   |
| `timeout`  | `number`       | `30000` | 查询超时(ms)     |
| `params`   | `QueryParam[]` | —       | 预处理参数       |
| `database` | `string`       | —       | 执行查询的数据库 |

#### 3.2.3 事件

| 事件              | 触发时机 | 事件数据                                   |
| ----------------- | -------- | ------------------------------------------ |
| `onDidStartQuery` | 查询开始 | `{ queryId, sql, connectionId, database }` |
| `onDidEndQuery`   | 查询结束 | `{ queryId, result: QueryResult }`         |

#### 3.2.4 执行流程

```
execute(adapter, sql, options):
1. 生成 queryId (UUID)
2. 创建 CancellationTokenSource
3. 记录到 runningQueries
4. 触发 onDidStartQuery 事件
5. 如指定 database，先执行 USE database
6. 使用 Promise.race 竞争：
   a. adapter.execute(sql, params)
   b. 超时 Promise（options.timeout ms 后 reject）
   c. CancellationToken（cancel() 调用后 reject）
   → 超时或取消发生时，若方言支持 cancel（supportsCancel=true），调用数据库端取消机制（MySQL: KILL QUERY connection_id）
7. 结果行数截断：超过 maxRows 时截断，设置 totalRowCount
8. 触发 onDidEndQuery 事件
9. 从 runningQueries 移除
10. 返回 QueryResult
```

#### 3.2.5 超时处理

- 超时后自动取消查询
- 返回 `QueryResult` 的 `status` 为 `'cancelled'`
- 调用 `adapter` 的取消机制（MySQL: `KILL QUERY`）

#### 3.2.6 取消处理

- 调用 `cancel(queryId)` 后：
    - 调用 `CancellationTokenSource.cancel()`
    - 尝试取消数据库端的查询
    - 返回 `status: 'cancelled'` 的结果

#### 3.2.6a 查询取消可靠性增强

为了提高查询取消的可靠性，增加以下机制：

| 机制         | 说明                                        |
| ------------ | ------------------------------------------- |
| 超时自动取消 | 超过 `query.timeout` 配置时间后自动取消查询 |
| 取消重试机制 | 首次取消失败后，间隔重试最多 3 次           |
| 降级处理     | 无法取消时，显示警告并提供手动处理建议      |
| 状态监控     | 实时显示查询执行状态和取消进度              |

**取消流程**：

1. 用户点击取消或超时触发
2. 调用 `KILL QUERY {connectionId}`（MySQL）
3. 检查查询是否真正终止
4. 如未终止，重试最多 3 次
5. 所有重试失败时，显示警告："查询可能仍在数据库端运行，建议手动检查"

新增配置项：

| 配置项                                      | 类型     | 默认值 | 说明             |
| ------------------------------------------- | -------- | ------ | ---------------- |
| `sql-all-in-one.execution.cancelRetries`    | `number` | `3`    | 取消操作重试次数 |
| `sql-all-in-one.execution.cancelRetryDelay` | `number` | `500`  | 取消重试间隔(ms) |

#### 3.2.7 执行命令

| 命令 ID                           | 快捷键                         | 说明               |
| --------------------------------- | ------------------------------ | ------------------ |
| `sql-all-in-one.executeQuery`     | `Ctrl+R` (Win) / `Cmd+R` (Mac) | 执行当前 SQL       |
| `sql-all-in-one.executeSelection` | `Ctrl+Shift+R`                 | 执行选中的 SQL     |
| `sql-all-in-one.cancelQuery`      | —                              | 取消正在执行的查询 |

**快捷键限定范围**：仅在 SQL 相关 `editorLangId` 下生效。

#### 3.2.8 执行命令流程

```
1. 获取活动连接（无连接时弹出快速选择）
2. 调用 SqlStatementDetector 提取 SQL
3. 调用 SafeQueryGuard 检查（见 P0-4）
4. 如有确认项，弹出确认对话框
5. 调用 QueryExecutor.execute()
6. 结果输出到 OutputChannel（本迭代）
   - 后续迭代将结果展示在 Webview 面板
7. 记录查询历史
```

#### 3.2.9 活动连接选择

- 优先使用当前活动连接
- 无活动连接时，弹出 QuickPick 列出所有已连接的数据库
- 选择后设为活动连接

### 3.3 验收标准

- [ ] 执行 SELECT 查询返回正确结果
- [ ] 执行 INSERT/UPDATE/DELETE 返回影响行数
- [ ] 超时查询自动取消
- [ ] 手动取消查询正常工作
- [ ] `Ctrl+R` 执行光标所在语句
- [ ] `Ctrl+Shift+R` 执行选区内容
- [ ] 无活动连接时弹出选择
- [ ] 执行错误时显示错误信息

## 4. P0-3：事务支持

### 4.1 背景与问题

数据编辑器（PRD-012）的批量提交、导入向导等场景需要事务保证原子性。PRD-008 已在 `IQueryAdapter` 中定义了事务 API，本节描述 MySQL 适配器的事务实现。

### 4.2 功能需求

#### 4.2.1 MySQL 事务实现

PRD-008 已在 `IQueryAdapter` 中定义了 `beginTransaction`、`commit`、`rollback` 方法。本节描述 MySQL 适配器的事务实现细节和工作流。

| 方法               | MySQL 实现                                               |
| ------------------ | -------------------------------------------------------- |
| `beginTransaction` | `pool.getConnection()` + `connection.beginTransaction()` |
| `commit`           | `connection.commit()` + `connection.release()`           |
| `rollback`         | `connection.rollback()` + `connection.release()`         |

> **注意**：事务期间使用专用连接（非连接池），事务完成后释放连接回池。

#### 4.2.2 事务执行流程

```
1. adapter.beginTransaction()
2. 执行多条 SQL（adapter.execute()）
3. 全部成功 → adapter.commit()
4. 任一失败 → adapter.rollback()
```

### 4.3 验收标准

- [ ] `beginTransaction` 获取专用连接
- [ ] 事务内多条 SQL 在同一连接上执行
- [ ] `commit` 后数据持久化
- [ ] `rollback` 后数据回滚
- [ ] 事务完成后连接释放回连接池

## 5. P0-4：安全拦截

### 5.1 背景与问题

执行危险 SQL（如无 WHERE 的 DELETE/UPDATE、DROP TABLE）可能导致数据丢失，需要拦截并确认。

### 5.2 功能需求

#### 5.2.1 SafeQueryGuard API

| 方法      | 参数  | 返回值              | 说明            |
| --------- | ----- | ------------------- | --------------- |
| `analyze` | `sql` | `SafetyCheckResult` | 分析 SQL 安全性 |

#### 5.2.2 SafetyCheckResult 结构

| 字段            | 类型                   | 说明                 |
| --------------- | ---------------------- | -------------------- |
| `safe`          | `boolean`              | 是否安全（无需确认） |
| `warnings`      | `SafetyWarning[]`      | 警告列表             |
| `confirmations` | `SafetyConfirmation[]` | 需要确认的项         |

#### 5.2.3 拦截规则

| 规则                    | 严重级别     | 说明             |
| ----------------------- | ------------ | ---------------- |
| DELETE 无 WHERE         | warning      | 可能删除全部数据 |
| UPDATE 无 WHERE         | warning      | 可能更新全部数据 |
| DROP TABLE              | confirmation | 删除表结构       |
| DROP DATABASE           | confirmation | 删除整个数据库   |
| TRUNCATE                | confirmation | 清空表数据       |
| ALTER TABLE DROP COLUMN | confirmation | 删除列           |

#### 5.2.4 拦截级别配置

配置项 `sql-all-in-one.safetyGuard.level`：

| 级别       | 行为                                            |
| ---------- | ----------------------------------------------- |
| `strict`   | 拦截所有规则（warning + confirmation 都需确认） |
| `moderate` | 仅拦截 confirmation 级别（默认）                |
| `off`      | 不拦截                                          |

#### 5.2.5 确认对话框

弹出 VSCode 的 `showWarningMessage` 对话框：

```
⚠️ 危险操作确认

即将执行: DROP TABLE users
该操作不可撤销，是否继续？

[继续执行] [取消]
```

- 选择"继续执行" → 正常执行
- 选择"取消" → 取消执行

#### 5.2.6 AST 分析实现

复用 `SqlParserEngine` 解析 SQL 为 AST，检查：

- `type === 'delete'` 且无 `where` 子句
- `type === 'update'` 且无 `where` 子句
- `type === 'drop'`
- `type === 'truncate'`
- `type === 'alter'` 且包含 `drop column` 操作

### 5.3 验收标准

- [ ] DELETE 无 WHERE 被拦截
- [ ] UPDATE 无 WHERE 被拦截
- [ ] DROP TABLE 弹出确认
- [ ] TRUNCATE 弹出确认
- [ ] `moderate` 级别仅拦截 DROP/TRUNCATE
- [ ] `off` 级别不拦截任何操作
- [ ] 确认对话框可继续或取消

## 6. P0-5：查询历史

### 6.1 背景与问题

Navicat 提供查询历史面板，记录所有执行过的查询，方便用户回顾和重执行。

### 6.2 功能需求

#### 6.2.1 QueryHistory API

| 方法        | 参数      | 返回值                | 说明            |
| ----------- | --------- | --------------------- | --------------- |
| `add`       | `entry`   | `void`                | 添加历史条目    |
| `getAll`    | 无        | `QueryHistoryEntry[]` | 返回所有历史    |
| `getRecent` | `count`   | `QueryHistoryEntry[]` | 返回最近 N 条   |
| `search`    | `keyword` | `QueryHistoryEntry[]` | 按 SQL 文本搜索 |
| `clear`     | 无        | `void`                | 清空历史        |

#### 6.2.2 QueryHistoryEntry 结构

| 字段             | 类型                   | 说明         |
| ---------------- | ---------------------- | ------------ |
| `id`             | `string`               | 唯一标识     |
| `sql`            | `string`               | SQL 文本     |
| `connectionId`   | `string`               | 连接 ID      |
| `connectionName` | `string`               | 连接名称     |
| `database`       | `string`               | 数据库名     |
| `executedAt`     | `Date`                 | 执行时间     |
| `executionTime`  | `number`               | 执行耗时(ms) |
| `rowCount`       | `number`               | 结果行数     |
| `affectedRows`   | `number?`              | 影响行数     |
| `status`         | `'success' \| 'error'` | 执行状态     |
| `errorMessage`   | `string?`              | 错误信息     |

#### 6.2.3 存储规格

| 项目     | 规格                          |
| -------- | ----------------------------- |
| 存储位置 | VSCode GlobalState            |
| Key      | `sql-all-in-one.queryHistory` |
| 最大条数 | 500（可通过配置调整）         |
| 溢出策略 | 超出时删除最旧的条目          |
| 持久化   | 跨会话保留                    |

#### 6.2.4 执行上下文保存

保存完整的查询执行上下文，支持重执行和追踪：

**增强的 QueryHistoryEntry**：

| 字段               | 类型                   | 说明           |
| ------------------ | ---------------------- | -------------- |
| `id`               | `string`               | 唯一标识       |
| `sql`              | `string`               | SQL 文本       |
| `connectionId`     | `string`               | 连接 ID        |
| `connectionName`   | `string`               | 连接名称       |
| `database`         | `string`               | 数据库名       |
| `params`           | `QueryParam[]`         | 查询参数       |
| `executedAt`       | `Date`                 | 执行时间       |
| `executionTime`    | `number`               | 执行耗时(ms)   |
| `rowCount`         | `number`               | 结果行数       |
| `affectedRows`     | `number?`              | 影响行数       |
| `status`           | `'success' \| 'error'` | 执行状态       |
| `errorMessage`     | `string?`              | 错误信息       |
| `executionContext` | `ExecutionContext`     | 完整执行上下文 |

**ExecutionContext 结构**：

| 字段             | 类型      | 说明                       |
| ---------------- | --------- | -------------------------- |
| `schemaVersion`  | `string?` | 当时的 Schema 版本（如有） |
| `configSnapshot` | `object`  | 执行时的配置快照           |
| `resultSummary`  | `object`  | 结果摘要（列名、类型等）   |

#### 6.2.4a 自动记录

- 每次查询执行完成后自动调用 `QueryHistory.add()`
- 成功和失败的查询均记录
- 取消的查询不记录

#### 6.2.4b 存储限制

为控制 GlobalState 存储空间：

- SQL 文本最多保存 2000 字符（超出截断并标注 `...(truncated)`）
- 如需要完整 SQL，用户可通过历史 ID 在其他存储中检索

#### 6.2.4c 查询片段保存

支持保存常用查询为可重用片段：

| 功能       | 说明                     |
| ---------- | ------------------------ |
| 保存为片段 | 从历史记录或当前查询保存 |
| 片段分类   | 支持文件夹式分类管理     |
| 片段标签   | 支持标签管理和搜索       |
| 团队共享   | 支持片段导入导出（可选） |

新增命令：

| 命令 ID                         | 说明               |
| ------------------------------- | ------------------ |
| `sql-all-in-one.saveAsSnippet`  | 保存当前查询为片段 |
| `sql-all-in-one.browseSnippets` | 浏览片段库         |

#### 6.2.5 历史命令

| 命令 ID                            | 说明                   |
| ---------------------------------- | ---------------------- |
| `sql-all-in-one.showQueryHistory`  | 显示查询历史 QuickPick |
| `sql-all-in-one.clearQueryHistory` | 清空查询历史           |

**历史 QuickPick 行为**：

- 列出最近的查询历史
- 显示：SQL 前 80 字符 + 连接名 + 耗时 + 时间
- 点击条目 → 在编辑器中打开 SQL
- 右键条目 → 复制 SQL / 删除条目

### 6.3 验收标准

## 9. 非功能需求

### 9.0 与 PRD-008 接口同步

PRD-008 已将 `IDatabaseAdapter.executeQuery` 和 `executeUpdate` 统一为 `execute` 方法，并在 `IQueryAdapter` 中定义了 `beginTransaction`、`commit`、`rollback` 事务方法。
本迭代中的 `QueryExecutor.execute()` 调用 `adapter.execute(sql, params)`，通过 `QueryResult.affectedRows` 是否存在区分查询和更新操作。事务相关方法直接使用 PRD-008 中 `IQueryAdapter` 定义的事务 API。
