## 2. P1-1：可视化执行计划

### 2.1 背景与问题

Navicat 的"可视化解释"功能将 EXPLAIN 结果以图形化方式展示，帮助用户理解查询执行路径和优化性能。

### 2.2 功能需求

#### 2.2.1 ExplainPlan 解析

**ExplainPlan API**：

| 方法                | 参数       | 返回值          | 说明                           |
| ------------------- | ---------- | --------------- | ------------------------------ |
| `parseMysqlExplain` | `raw: any` | `ExplainResult` | 解析 MySQL EXPLAIN FORMAT=JSON |

**ExplainResult 结构**：

| 字段     | 类型                           | 说明           |
| -------- | ------------------------------ | -------------- |
| `format` | `'json' \| 'text' \| 'visual'` | 格式类型       |
| `raw`    | `any`                          | 原始数据       |
| `nodes`  | `ExplainNode[]`                | 解析后的节点树 |

**ExplainNode 结构**：

| 字段        | 类型            | 说明                                                 |
| ----------- | --------------- | ---------------------------------------------------- |
| `id`        | `number`        | 节点 ID                                              |
| `operation` | `string`        | 操作类型（TABLE SCAN / INDEX SCAN / NESTED LOOP 等） |
| `table`     | `string?`       | 涉及的表                                             |
| `rows`      | `number?`       | 扫描行数                                             |
| `cost`      | `number?`       | 成本                                                 |
| `key`       | `string?`       | 使用的索引                                           |
| `extra`     | `string?`       | 额外信息                                             |
| `children`  | `ExplainNode[]` | 子节点                                               |

#### 2.2.2 ExplainPlanPanel

**面板布局**：

```
┌──────────────────────────────────────────────────────────┐
│ 执行计划 - SELECT * FROM users WHERE status = 'active'   │
├──────────────────────────────────────────────────────────┤
│ [可视化] [表格] [JSON]                                    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  ┌──────────────┐                                        │
│  │ SELECT       │  扫描行: 1234  成本: 0.35               │
│  └──────┬───────┘                                        │
│         │                                                │
│  ┌──────┴───────┐                                        │
│  │ TABLE SCAN   │  users  使用索引: idx_status            │
│  │ (ref)        │  扫描行: 56  成本: 0.12                 │
│  └──────────────┘                                        │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ 优化建议: 考虑添加复合索引 (status, created_at)           │
└──────────────────────────────────────────────────────────┘
```

#### 2.2.3 三种视图

| 视图       | 说明                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| **可视化** | 树形/流程图展示执行节点，节点大小反映成本，颜色反映类型                 |
| **表格**   | 传统 EXPLAIN 结果表格（id, select_type, table, type, key, rows, Extra） |
| **JSON**   | 原始 EXPLAIN FORMAT=JSON 输出，格式化展示                               |

#### 2.2.4 可视化视图节点颜色

| 操作类型    | 颜色    | 说明             |
| ----------- | ------- | ---------------- |
| TABLE SCAN  | 🔴 红色 | 全表扫描，需优化 |
| INDEX SCAN  | 🟡 黄色 | 索引扫描         |
| INDEX SEEK  | 🟢 绿色 | 索引查找，高效   |
| NESTED LOOP | 🔵 蓝色 | 嵌套循环连接     |
| SORT        | 🟠 橙色 | 排序操作         |
| TEMPORARY   | 🟣 紫色 | 临时表           |

#### 2.2.5 优化建议

基于 EXPLAIN 结果自动生成优化建议：

| 检测条件                  | 建议                          |
| ------------------------- | ----------------------------- |
| `type = ALL`（全表扫描）  | 考虑为 WHERE 条件添加索引     |
| `Extra = Using filesort`  | 考虑为 ORDER BY 列添加索引    |
| `Extra = Using temporary` | 考虑优化 GROUP BY 或 DISTINCT |
| `rows` 远大于实际结果     | 索引选择性低，考虑复合索引    |
| `key = NULL`              | 未使用索引，考虑添加          |

#### 2.2.5a EXPLAIN ANALYZE 支持（MySQL 8.0.18+）

MySQL 8.0.18+ 支持 `EXPLAIN ANALYZE`，可获取实际执行统计（非估算）。适配器的 `getExplainPlan` 方法根据数据库版本动态选择：

- MySQL < 8.0.18：使用 `EXPLAIN FORMAT=JSON`
- MySQL >= 8.0.18：执行计划面板增加"实际执行"按钮，使用 `EXPLAIN ANALYZE`
    - 注意：`EXPLAIN ANALYZE` 会实际执行 SQL（包括副作用），仅用于 SELECT 查询
    - 执行面板标题区分标注："EXPLAIN（估算）"或"EXPLAIN ANALYZE（实际执行）"

适配器的 `supportsExplainAnalyze`：MySQL 版本 >= 8.0.18 时为 `true`，< 8.0.18 时为 `false`。在 `testConnection` 获取 `serverVersion` 后解析版本号判断。

#### 2.2.6 集成到结果面板

结果面板新增"执行计划"标签（第四个标签），点击后对当前 SQL 执行 EXPLAIN。

**命令**：

| 命令 ID                       | 说明                    |
| ----------------------------- | ----------------------- |
| `sql-all-in-one.explainQuery` | 查看当前 SQL 的执行计划 |

## 3. P1-2：SSH 隧道

### 3.1 背景与问题

生产数据库通常在内网，需要通过 SSH 跳板机连接。Navicat 的 SSH 隧道功能是其企业级特性之一。

### 3.2 功能需求

#### 3.2.1 SshTunnel API

| 方法           | 参数                                        | 返回值                  | 说明             |
| -------------- | ------------------------------------------- | ----------------------- | ---------------- |
| `open`         | `config: SshConfig, targetHost, targetPort` | `Promise<TunnelResult>` | 建立 SSH 隧道    |
| `close`        | 无                                          | `Promise<void>`         | 关闭隧道         |
| `getLocalPort` | 无                                          | `number`                | 获取本地映射端口 |
| `isOpen`       | 无                                          | `boolean`               | 隧道是否打开     |

**TunnelResult 结构**：

| 字段        | 类型     | 说明                           |
| ----------- | -------- | ------------------------------ |
| `localHost` | `string` | 本地主机（通常为 `127.0.0.1`） |
| `localPort` | `number` | 本地映射端口                   |

#### 3.2.2 技术实现

- 使用 `ssh2` 库建立 SSH 连接
- 通过 `ssh2.Client` 连接到 SSH 服务器后，使用 `forwardIn()` 在本地监听端口，再通过 `forwardOut()` 建立到远程数据库的端口转发
- 本地监听随机可用端口（`listen(0)`）
- 将本地端口流量通过 SSH 隧道转发到远程数据库端口

**连接流程**（在 `ConnectionManager` 中）：

```
1. 创建 `ssh2.Client` 实例，连接到 SSH 服务器
2. 认证（密码或私钥）
3. 调用 `client.forwardIn('127.0.0.1', 0)` 在本地监听随机端口
4. 当数据库连接请求到达本地端口时，调用 `client.forwardOut()` 转发到目标数据库的 host:port
5. 获取实际分配的 localPort
6. 修改 ConnectionConfig 的 host 为 '127.0.0.1'，port 为 localPort
7. 适配器通过本地端口连接数据库
```

> **密码存储**：SSH 密码和私钥密码通过 VSCode SecretStorage 存储，Key 遵循 PRD-008 §5.2.1 定义的规范：
>
> - SSH 密码：`sql-all-in-one.ssh.password.{connectionId}`
> - SSH 私钥密码：`sql-all-in-one.ssh.passphrase.{connectionId}`

#### 3.2.3 连接流程修改

修改 `ConnectionManager.connect()` 流程：

```
1. 检查 SSH 配置是否启用
2. 启用 →
   a. 创建 SshTunnel 实例
   b. 调用 tunnel.open(sshConfig, dbHost, dbPort)
   c. 获取 localPort
   d. 修改 ConnectionConfig 的 host 为 '127.0.0.1'，port 为 localPort
3. 未启用 → 正常连接
4. 创建适配器并连接
5. 断开时同时关闭 SSH 隧道
```

#### 3.2.4 SSH 认证方式

| 方式     | 说明                                                      |
| -------- | --------------------------------------------------------- |
| 密码认证 | 使用 `password` 字段                                      |
| 公钥认证 | 使用 `privateKey` 字段指定私钥文件路径，可选 `passphrase` |

#### 3.2.5 错误处理

| 错误         | 处理方式                      |
| ------------ | ----------------------------- |
| SSH 连接超时 | 提示检查 SSH 服务器地址和端口 |
| SSH 认证失败 | 提示检查用户名和密码/私钥     |
| 私钥格式错误 | 提示检查私钥文件格式          |
| 端口转发失败 | 提示检查目标数据库地址和端口  |

## 4. P1-3：数据导入

### 4.1 背景与问题

Navicat 的导入向导支持从多种格式导入数据到表，是数据迁移的常用功能。

### 4.2 功能需求

#### 4.2.1 DataImporter API

| 方法             | 参数                                    | 返回值                  | 说明         |
| ---------------- | --------------------------------------- | ----------------------- | ------------ |
| `importFromCsv`  | `filePath, tableName, mapping, options` | `Promise<ImportResult>` | CSV 导入     |
| `importFromJson` | `filePath, tableName, options`          | `Promise<ImportResult>` | JSON 导入    |
| `importFromSql`  | `filePath`                              | `Promise<ImportResult>` | SQL 文件执行 |

**ImportResult 结构**：

| 字段           | 类型            | 说明         |
| -------------- | --------------- | ------------ |
| `success`      | `boolean`       | 是否成功     |
| `totalRows`    | `number`        | 总行数       |
| `importedRows` | `number`        | 成功导入行数 |
| `skippedRows`  | `number`        | 跳过行数     |
| `errors`       | `ImportError[]` | 错误列表     |

**ImportError 结构**：

| 字段      | 类型     | 说明     |
| --------- | -------- | -------- |
| `row`     | `number` | 行号     |
| `message` | `string` | 错误信息 |
| `data`    | `string` | 行数据   |

#### 4.2.2 导入格式

| 格式 | 说明                      |
| ---- | ------------------------- |
| CSV  | 带表头，可配置分隔符/编码 |
| JSON | 数组格式 `[{}, {}]`       |
| SQL  | 执行 SQL 文件中的语句     |

#### 4.2.3 导入向导

向导式流程（Webview 实现）：

**步骤 1：选择数据源**

| 字段     | 类型     | 说明             |
| -------- | -------- | ---------------- |
| 文件路径 | 文件选择 | 选择导入文件     |
| 文件格式 | 自动检测 | CSV / JSON / SQL |

**步骤 2：选择目标表**

| 字段     | 类型     | 说明                   |
| -------- | -------- | ---------------------- |
| 目标表   | 下拉选择 | 选择已有表或新建表     |
| 新建表名 | 文本输入 | 选择"新建表"时输入表名 |

**步骤 3：字段映射**

| 源列       | 目标列     | 说明             |
| ---------- | ---------- | ---------------- |
| 源文件列名 | 目标表列名 | 下拉选择映射关系 |
| —          | 跳过       | 不导入该列       |

- 自动匹配：源列名与目标列名相同时自动映射
- 手动调整：下拉选择目标列或"跳过"

**步骤 4：导入选项**

| 选项       | 类型 | 默认值 | 说明               |
| ---------- | ---- | ------ | ------------------ |
| 遇到错误时 | 单选 | 跳过   | 跳过 / 中止        |
| 去重策略   | 单选 | 忽略   | 忽略 / 跳过 / 更新 |
| 批量大小   | 数字 | 100    | 每批导入的行数     |
| 预览行数   | 数字 | 10     | 预览显示的行数     |

**步骤 5：预览并执行**

- 显示前 10 行数据预览
- 显示映射关系
- 点击"开始导入"执行
- 使用 VSCode `Progress` API 显示进度条（`vscode.window.withProgress`）
- Webview 中显示实时进度：
    - 进度条 + 百分比
    - "已导入 1,234 / 10,000 行 (12.3%)"
    - "耗时: 12s 预计剩余: 85s"
    - "速度: 103 行/秒"
- 进度条显示导入进度
- 完成后显示导入结果统计

#### 4.2.4 CSV 导入规格

| 项目   | 说明                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| 分隔符 | 自动检测（逗号/制表符/分号），可手动指定                                                                    |
| 编码   | 自动检测（使用 `jschardet` / `chardet` 或文件 BOM 标记），检测失败时手动选择（UTF-8/GBK/GB2312/Latin-1 等） |
| 表头   | 第一行作为列名                                                                                              |
| 引号   | 双引号包裹的字段                                                                                            |
| 转义   | 反斜杠转义                                                                                                  |

#### 4.2.5 命令

| 命令 ID                     | 说明             |
| --------------------------- | ---------------- |
| `sql-all-in-one.importData` | 打开数据导入向导 |
