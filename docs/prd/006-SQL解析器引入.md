# PRD-006: 引入 SQL 解析器替代正则分析

## 一、背景与动机

### 1.1 当前问题

SQL All in One 扩展中，Provider 层（诊断、Lint、增强检查）大量使用正则表达式对原始 SQL 文本进行分析，存在四类固有限制：

| 限制类别 | 根因 | 后果 |
|----------|------|------|
| **嵌套/复杂场景** | 正则无法表达递归语法结构 | 极端 SQL 可能误报 |
| **字符串/注释中的关键字** | 大部分检查未排除字符串和注释上下文 | `'SELECT FROM table'` 会被误检测 |
| **跨语句边界** | 部分检查（如 HAVING/GROUP BY）不区分多语句 | 多语句场景可能漏报 |
| **嵌套函数映射** | 正则扁平匹配，无法处理 `IFNULL(COALESCE(a,b),c)` 等嵌套 | 嵌套函数转换可能出错 |

此外，Converter（HIVE↔MySQL CREATE TABLE 互转）和 Completion（代码补全）同样依赖正则，存在类似局限。

### 1.2 已有机遇

项目**已有完整的 AST 解析链**（Nearley Parser + Tokenizer），但 Provider/Converter/Completion 层绕过了它。本次改造直接引入成熟的第三方解析器 `node-sql-parser`，全面替代正则分析。

---

## 二、设计目标

| 目标 | 说明 |
|------|------|
| **全面消除正则分析** | Formatter、Diagnostics、Linter、EnhancedChecker、Converter、Completion 全部基于 AST |
| **零误报** | 注释和字符串中的关键字不会被误检测 |
| **精确嵌套处理** | 递归 AST 遍历天然支持任意嵌套深度的 SQL 结构 |
| **多语句感知** | AST 支持分号分隔的多语句，逐句分析 |
| **方言正确映射** | 8 种方言正确对应 node-sql-parser 的解析器 |

---

## 三、解析器选型

### 3.1 选择：node-sql-parser

**优势**：
- 成熟的 npm 包，活跃维护（5.x 版本）
- 支持 12+ 种 SQL 方言
- 内置位置信息（行列号）、表名/列名提取
- 双向能力：SQL → AST（`astify`）+ AST → SQL（`sqlify`）
- 完整 TypeScript 类型定义

**API 示例**：
```typescript
const { Parser } = require('node-sql-parser');
const parser = new Parser();

const ast = parser.astify('SELECT * FROM t', {
    database: 'MySQL',
    parseOptions: { includeLocations: true }
});

const sql = parser.sqlify(ast, { database: 'PostgreSQL' });
const { tableList, columnList, ast } = parser.parse(sql, opt);
```

### 3.2 方言映射

| 项目方言 | node-sql-parser 方言 | 说明 |
|----------|---------------------|------|
| mysql | MySQL | 完全匹配 |
| hive | Hive | 完全匹配 |
| spark | FlinkSQL | Spark SQL 与 Flink SQL 语法高度一致 |
| postgresql | PostgreSQL | 完全匹配 |
| bigquery | BigQuery | 完全匹配 |
| snowflake | Snowflake | alpha 版本，基本可用 |
| sqlite | SQLite | 完全匹配 |

> **弃用方言**：Oracle (PL/SQL) 和 Presto/Trino 不再支持，因为 node-sql-parser 无对应解析器且无合适的替代映射。

### 4.1 封装层：SqlParserEngine

```typescript
// src/parser/SqlParserEngine.ts
class SqlParserEngine {
    private parser: Parser;

    constructor() {
        this.parser = new Parser();
    }

    astify(sql: string, dialect: SqlDialect): ASTNode {
        const mappedDialect = dialectMapper.toNodeSqlParser(dialect);
        try {
            return this.parser.astify(sql, {
                database: mappedDialect,
                parseOptions: { includeLocations: true }
            });
        } catch (e) {
            throw new ParseError(dialect, sql, e);
        }
    }

    sqlify(ast: ASTNode, dialect: SqlDialect): string {
        return this.parser.sqlify(ast, {
            database: dialectMapper.toNodeSqlParser(dialect)
        });
    }

    parse(sql: string, dialect: SqlDialect): { tableList: string[]; columnList: string[]; ast: ASTNode } {
        return this.parser.parse(sql, {
            database: dialectMapper.toNodeSqlParser(dialect)
        });
    }
}
```

## 五、各模块重写设计

### 5.1 Formatter 格式化器

**当前**：Tokenizer（正则词法）→ Nearley Parser → `ExpressionFormatter` 遍历 Nearley AST 节点格式化。

**重写后**：`SqlParserEngine.astify()` → `AstFormatter` 遍历 node-sql-parser AST 格式化。

**node-sql-parser AST 关键节点与格式化操作对照**：

| AST 节点 | 格式化操作 |
|----------|-----------|
| `{ type: 'select', columns, from, where, ... }` | SELECT/FROM/WHERE/GROUP BY/HAVING/ORDER BY/LIMIT 各子句的缩进和换行控制 |
| `{ type: 'column_ref', table, column }` | `table.column` 连接格式化 |
| `{ expr: { type: 'function', name, args }, as }` | 函数名大小写、参数逗号、别名格式化 |
| `{ type: 'binary_expr', operator, left, right }` | AND/OR 换行策略、操作符空格 |
| `{ type: 'case', expr, whens, else }` | CASE/WHEN/THEN/ELSE/END 缩进对齐 |
| `{ type: 'aggr_func', name, args }` | 聚合函数格式化 |
| `from: [{ db, table, as, join }]` | 多表 JOIN 层级格式化 |
| `with: [{ name, columns, stmt }]` | CTE 声明格式化 |
| `{ type: 'expr_list', value }` | 表达式列表逗号分隔和换行 |
| `window` 节点 | OVER/PARTITION BY/ORDER BY 格式化 |
| `{ type: 'insert', table, columns, values }` | INSERT 列名/值格式化 |
| `{ type: 'create', keyword, table, create_definitions }` | CREATE TABLE 列定义格式化 |

**FormatOptions 兼容**：全部 82 个配置项（39 已有 + 43 新增），在新 `AstFormatter` 中按节点类型分别实现。

### 5.2 SqlDiagnosticsProvider（诊断）

8 个检查方法从正则匹配 → AST 字段检查：

| # | 检查项 | 旧方案（正则） | 新方案（AST） |
|---|--------|-------------|-------------|
| 1 | 逗号后跟 FROM | `/,(\\s*)\\bfrom\\b/gi` 全文搜索 | 遍历 SELECT columns，检查末位逗号 |
| 2 | SELECT 无列 | `\\bselect\\b` + 手工括号深度 | `select.columns` 为空或仅 `*` |
| 3 | FROM 无表 | `\\bfrom\\b` + 子句边界正则 | `select.from` 数组为空 |
| 4 | 括号不匹配 | **逐字符状态机** | **不再需要！** 解析器已处理 |
| 5 | 未闭合字符串 | **逐字符状态机** | **不再需要！** 解析器已处理 |
| 6 | ORDER BY 无列 | `\\border\\s+by\\b` | `select.orderby` 为空 |
| 7 | WHERE 无条件 | `\\bwhere\\b` | `select.where === null` |
| 8 | GROUP BY 无列 | `\\bgroup\\s+by\\b` | `select.groupby` 为空 |

### 5.3 EnhancedSqlChecker（增强检查）

15 个检查方法全部重写：

| # | 检查项 | AST 检查逻辑 |
|---|--------|------------|
| 1 | HAVING 无 GROUP BY | `select.having !== null && select.groupby === null` |
| 2 | LIMIT 无效值 | 检查 `select.limit` 节点的 value 字段 |
| 3 | 重复表别名 | 收集 `from[].as` 做 Set 去重 |
| 4 | 保留字做别名 | 遍历别名与关键字表匹配 |
| 5 | JOIN 缺少 ON/USING | 检查 JOIN 节点的 `on` 字段 |
| 6 | SELECT 无 FROM | `select.from === null`（排除 `SELECT now()` 等） |
| 7 | DISTINCT 位置不当 | `select.distinct` 在 columns 中的位置检查 |
| 8 | WHERE 中聚合函数 | 遍历 `where` 子树查找 `aggr_func` 节点 |
| 9 | UPDATE 误用 * | 检查 UPDATE SET 表达式中的 `column_ref` |
| 10 | INSERT 无列名 | 检查 INSERT 的 `columns` 数组 |
| 11 | CASE 不完整 | 递归检查 CASE 节点的 `whens`/`else` |
| 12 | COUNT(DISTINCT *) | `distinct` + `column_ref.column === '*'` |
| 13 | 子查询无别名 | 递归检查 FROM 子查询的 `as` 字段 |
| 14 | = NULL 可疑写法 | 遍历 `binary_expr`，`operator` 为比较 + `right` 为 null |
| 15 | 方言特有日期函数 | 匹配函数名 + 检测当前方言 |

### 5.4 SqlLinter（Lint 规则）

12 个检查方法全部重写：

| # | 检查项 | AST 检查逻辑 |
|---|--------|------------|
| 1 | SELECT * | columns 中 `column_ref.column === '*'` |
| 2 | JOIN 无显式类型 | JOIN 节点的 `join` 类型字段 |
| 3 | LIMIT 无 ORDER BY | `select.limit !== null && select.orderby === null` |
| 4 | INSERT 列值数量不匹配 | `insert.columns.length !== insert.values[0].value.length` |
| 5 | CREATE TABLE 无主键 | 遍历 `create_definitions` 找 `primary key` 约束 |
| 6 | INSERT SELECT * | INSERT 的 SELECT 子句中检测 `column_ref.column === '*'` |
| 7 | 重复列别名 | 收集 columns 的 `as` 做去重 |
| 8 | IFNULL→COALESCE | 函数名匹配 `ifnull`/`isnull` |
| 9 | 方言函数→标准函数 | 函数名 + 方言上下文匹配 |
| 10 | 关联子查询警告 | WHERE 中子查询引用外部列 |
| 11 | 隐式列别名 | `expr_list` 中无 `as` 的表达式 |
| 12 | 缺少查询注释 | AST 顶层语句数量 + JOIN/子查询复杂度 |

### 5.5 Converter（HIVE↔MySQL CREATE TABLE 互转）

**当前**：正则提取列定义，逐字段替换类型和属性。

**重写后**：直接操作 AST 节点，完成后 `sqlify()`：

```typescript
function convertCreateTable(sql: string, fromDialect: string, toDialect: string): string {
    const ast = parser.astify(sql, { database: fromDialect });

    ast.create_definitions.forEach(def => {
        if (def.resource === 'column') {
            def.definition.dataType = convertDataType(def.definition.dataType, toDialect);
        }
        if (def.resource === 'index' || def.resource === 'constraint') {
            convertConstraint(def, toDialect);
        }
    });

    ast.table_options = convertTableOptions(ast.table_options, toDialect);

    return parser.sqlify(ast, { database: toDialect });
}
```

**优势**：
- 不再需要手工追踪括号深度和字符串边界
- 嵌套 CREATE TABLE（`CREATE TABLE AS SELECT`）自然支持
- 转换前后的 SQL 都是合法 AST，不会产生语法错误

### 5.6 Completion（代码补全）

**当前**：基于光标位置和文本正则匹配。

**重写后**：解析到光标位置，获取上下文类型：

```typescript
type CompletionContext =
    | 'select_columns'   // SELECT 后的列名/函数补全
    | 'from_table'       // FROM 后的表名补全
    | 'where_expr'       // WHERE 中的列名/操作符/函数补全
    | 'join_type'        // JOIN 类型补全
    | 'on_condition'     // ON 条件中的列名补全
    | 'groupby_columns'  // GROUP BY 中的列名补全
    | 'orderby_columns'  // ORDER BY 中的列名补全
    | 'window_func'      // OVER 中的窗口函数补全
    | 'cte_name'         // WITH 子句中的 CTE 名称
    | 'function_args'    // 函数参数补全（含签名帮助）
    | 'case_when'        // CASE WHEN 补全
    | 'unknown';         // 兜底：全部补全

function findCursorContext(ast: ASTNode, position: Position): CompletionContext {
    // 遍历 AST，根据 position 定位到具体节点类型
    // 返回当前光标位置应有的补全类型
}
```

**优势**：
- 上下文感知：SELECT 后推荐列名/函数，FROM 后推荐表名
- 字符串/注释中自动跳过，不触发补全
- CTE 名称直接从 `with.name` 读取
