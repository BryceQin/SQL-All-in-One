## 1. 背景与目标

### 1.1 现状（问题）

`contributes.languages` 注册了 12 个语言 ID 及扩展名，2.35.0 补齐了 TextMate 语法（着色），但始终没有语言配置 —— `contributes.languages[].configuration` 字段缺失，`src/` 下也无 `setLanguageConfiguration` 调用。语言配置决定 VSCode 的基础编辑行为：

- `Cmd+/` / `Ctrl+/` 注释切换（行注释 `--`、块注释 `/* */`）
- 括号匹配高亮与括号颜色分级
- 引号 / 括号自动闭合
- 选中环绕（surround selection）

结果：`.hql` / `.mysql` / `.sparksql` 等所有插件自定义语言 ID 上 `Cmd+/` 无反应、括号匹配与自动闭合缺失。`.sql` 可用仅因 VSCode 内置 SQL 扩展（sql-language-features）自带语言配置。

### 1.2 目标

为 12 个语言 ID 提供方言感知的语言配置，且派生数据与 tokenizer / 语法高亮零漂移。

## 2. 方案选型

| 选项 | 结论 |
| --- | --- |
| A. 手写 12 份静态 JSON | ✗ 第二份清单必然漂移（023 对语法文件已否决同思路） |
| B. 激活时 `setLanguageConfiguration` API 注册 | ✗ 需插件激活才生效；静态贡献打开文件即生效、声明式可审 |
| C. 生成管线：tokenizerOptions → 生成器 → 静态 JSON 入库 | ✓ 与 023 语法高亮同构，单一数据源 |

选 C。生成物入库（构建环境可能没有完整工具链），golden 测试防漂移。

## 3. 派生规则

| 语言配置字段 | 数据来源 | 规则 |
| --- | --- | --- |
| `comments.lineComment` | `lineCommentTypes` | 取首个（SQL 标准 `--`；VSCode 仅支持单一行注释符） |
| `comments.blockComment` | Tokenizer 硬编码 | 全方言 `/* */`（Tokenizer.ts 块注释对所有方言统一启用） |
| `brackets` / 自动闭合 `[]` | `extraParens` ∪ `identTypes` | 任一使用 `[]` 即启用：Hive/Spark/PG/BigQuery/SQLite 经 `extraParens`，SQL Server 经 `identTypes` |
| 自动闭合引号 | `stringTypes` ∪ `identTypes` | 实际出现的引号字符 `'` `"` `` ` ``；`notIn: ["string", "comment"]` |
| `surroundingPairs` | `autoClosingPairs` | 显式生成便于审阅（缺省时 VSCode 亦回退） |
| `onEnterRules` / `indentationRules` / `wordPattern` | — | **不生成**：无确定数据来源，错误的缩进规则比缺失更糟 |

### 3.1 有意差异与边界

- MySQL/BigQuery/StarRocks 的 `#` 行注释不参与 `Cmd+/`（VSCode 单一行注释符限制，取 SQL 标准 `--`）；`#` 仍由 TextMate 语法着色。
- `{}` 不进 brackets：hive/spark 的 `${var}` 是 `requirePrefix` 变量语法，tokenizer 亦不将其作为括号。
- `sql` 语言 ID 的配置与 VSCode 内置 SQL 扩展合并（后注册者优先）：行为差异仅为 brackets 少了无意义的 `{}`、自动闭合多出反引号 —— 与 2.35.0 覆盖内置 sql 语法同一先例。
- `sqlserver` 的 `[]` 来自 `identTypes`（引用标识符）而非 `extraParens`，派生规则取并集。

## 4. 实现组成

- `src/grammar/languageConfigBuilder.ts`：生成器（`buildLanguageConfiguration`）
- `scripts/generate-language-configs.ts`：构建脚本（langId 查重 + 写盘，CI-safe）
- `language-configurations/<langId>.language-configuration.json` × 12：生成物入库
- `package.json`：`contributes.languages[].configuration` 挂接 12 条；新增 `generate-language-configs` 脚本并接入 `vscode:prepublish` / `esbuild` / `esbuild-base` 链
- `.vscodeignore`：无需改动（`language-configurations/` 默认随包，`scripts/**` 本就剔除）

## 5. 测试策略

`src/test/languageConfig.test.ts`（与 grammar.test.ts 同构）：

1. **结构**：12 份文件存在，覆盖 `dialectGrammarConfigs` 全部语言
2. **golden 防漂移**：磁盘文件 == `buildLanguageConfiguration` 输出（字节级）
3. **package.json 一致性**：每个 language 条目挂接 `configuration`，路径符合 `./language-configurations/<id>.language-configuration.json` 约定且存在
4. **派生断言**：全方言 `--` / `/* */` / 圆括号 / `notIn`；方言差异快照 —— 方括号 6 有（hive/spark/postgresql/bigquery/sqlite/sqlserver）6 无（sql/mysql/flinksql/starrocks/plsql/dameng），反引号 8 有 3 无（sqlserver/plsql/dameng）

## 6. 验收标准

- [x] 任一注册语言 ID 的文件中 `Cmd+/` 切换 `--` 行注释、`Shift+Alt+A` 切换 `/* */` 块注释
- [x] 括号匹配 / 引号自动闭合按方言工作（Hive `[]`、MySQL 反引号、SQL Server `[]` 无反引号）
- [x] golden 测试锁定生成物，方言配置更新后 `npm run generate-language-configs` 再生成
- [x] CI 全绿（tsc --noEmit / oxlint / vscode:prepublish / 全量测试）

## 7. 风险与边界

- **多扩展合并**：`sql` 语言 ID 与内置扩展的合并行为见 §3.1，影响为净改进。
- **生成物漂移**：由 golden 测试 + `vscode:prepublish` 链双保险（打包前必然再生成）。
- **运行时零成本**：语言配置由 VSCode 渲染进程静态加载，不新增 activationEvents、不进 esbuild bundle（生成器仅构建期使用）。
