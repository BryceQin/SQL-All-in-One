# PRD-005: 悬停提示功能（Hover Provider）

## 一、概述

为 SQL All in One 扩展新增 VS Code HoverProvider 支持，提供三类悬停提示：
- **函数悬停**：显示函数签名、参数列表、返回类型和描述
- **关键字悬停**：显示关键字的语法模板、用途说明和示例代码
- **参数引用悬停**：显示参数名及其在文档中的全部引用位置

---

## 二、设计原则

| 原则 | 说明 |
|------|------|
| **Markdown 富文本** | Hover 内容使用 VS Code MarkdownString 渲染，分段显示，排版清晰 |
| **方言感知** | 根据当前文档的 SQL 方言（10 种）提供对应语言的函数和关键字信息 |
| **按需加载** | 关键字和函数数据仅在首次触发时加载并缓存，不预构建 |
| **性能优先** | 参数引用扫描结果缓存，仅在文档内容变更后重新计算 |
| **一致注册模式** | 遵循现有 Provider 的注册方式，为每种方言分别注册 |
| **向后兼容** | 新增 `enableHover` 配置项，默认开启，关闭后零开销 |
| **复用已有数据** | 函数签名数据直接复用 `src/languages/*/` 目录下的 FunctionSignature 数据 |

## 四、数据模型

### 4.1 HoverResolver 接口

```typescript
interface HoverResolver {
    resolve(
        word: string,
        dialect: SqlDialect,
        document: vscode.TextDocument
    ): vscode.Hover | null;
}
```

### 4.2 KeywordInfo 接口

```typescript
interface KeywordInfo {
    keyword: string;           // 关键字名称，如 'SELECT'、'LATERAL VIEW'
    syntax: string;            // 语法模板
    description: string;       // 功能说明
    example?: string;          // 使用示例（可选）
    category: KeywordCategory; // 分类
}

type KeywordCategory =
    | 'query'        // 查询子句: SELECT, FROM, WHERE, GROUP BY, HAVING...
    | 'join'         // 连接: JOIN, LEFT JOIN, CROSS JOIN...
    | 'setop'        // 集合运算: UNION, INTERSECT, EXCEPT...
    | 'dml'          // 数据操作: INSERT, UPDATE, DELETE, MERGE...
    | 'ddl'          // 数据定义: CREATE TABLE, ALTER TABLE, DROP...
    | 'window'       // 窗口函数: OVER, PARTITION BY, ROWS BETWEEN...
    | 'transaction'  // 事务: BEGIN, COMMIT, ROLLBACK...
    | 'auxiliary'    // 辅助命令: SHOW, DESCRIBE, EXPLAIN, USE...
    | 'conditional'  // 条件表达式: CASE WHEN, IF, COALESCE...
    | 'type'         // 数据类型: INT, STRING, DECIMAL, ARRAY, MAP...
    | 'hint'         // 方言特有: LATERAL VIEW, EXPLODE, DISTRIBUTE BY...
```

## 五、架构设计

### 5.1 核心数据流

```
用户鼠标悬停
    ↓
SqlHoverProvider.provideHover(document, position)
    ↓
extractWordAtPosition() → 提取光标处单词
    ↓
按优先级顺序询问每个 HoverResolver:
    ├── ParameterHoverResolver（优先级最高，匹配 ${paramName} 模式）
    ├── FunctionHoverResolver  （匹配已知函数名，大小写不敏感）
    └── KeywordHoverResolver   （匹配已知关键字，大小写不敏感）
    ↓
Resolver.buildHover() → 构造 vscode.MarkdownString
    ↓
返回 vscode.Hover（首个匹配即返回，不再继续询问后续 Resolver）
```

### 5.2 SqlHoverProvider 核心实现

```typescript
class SqlHoverProvider implements vscode.HoverProvider {
    private resolvers: HoverResolver[];
    private keywordCache: Map<SqlDialect, KeywordInfo[]>;

    constructor() {
        this.resolvers = [
            new ParameterHoverResolver(),
            new FunctionHoverResolver(),
            new KeywordHoverResolver(),
        ];
    }

    provideHover(
        document: vscode.TextDocument,
        position: vscode.Position
    ): vscode.Hover | null {
        // 检查配置开关
        const config = vscode.workspace.getConfiguration('SQL-All-in-One');
        if (!config.get<boolean>('enableHover', true)) return null;

        const dialect = getCurrentDialect(document);
        if (!dialect) return null;

        const word = extractWordAtPosition(document, position);
        if (!word) return null;

        for (const resolver of this.resolvers) {
            const result = resolver.resolve(word, dialect, document);
            if (result) return result;
        }
        return null;
    }
}
```

## 六、各 Resolver 详细设计

### 6.1 FunctionHoverResolver — 函数悬停

**复用已有数据**：`src/languages/{dialect}/{dialect}.functions.ts` 中的 `FunctionSignature` 接口：

```typescript
interface FunctionSignature {
    name: string;        // 函数名
    params: string[];    // 参数列表
    returnType?: string; // 返回类型
    description: string; // 描述
    category: FunctionCategory;
    examples?: string[]; // 已有部分函数包含示例
}
```

**匹配逻辑**：
1. 根据 dialect 获取对应的函数签名列表
2. 对悬停处的单词进行大小写不敏感的精确匹配
3. 匹配成功时构造 Markdown 内容

**Markdown 渲染模板**：

```
### {FUNCTION_NAME}({PARAMS})

---
{category_label} — {description}

**返回类型** `{returnType}`

**语法**
\`\`\`sql
{FUNCTION_NAME}({params})
\`\`\`

**示例**
\`\`\`sql
{example}
\`\`\`
```

**示例效果**（悬停在 `ROW_NUMBER` 上）：

> ### ROW_NUMBER()
>
> ---
> 窗口函数 — 为结果集的每一行分配唯一的连续整数，从 1 开始
>
> **返回类型** `INT`
>
> **语法**
> ```sql
> ROW_NUMBER() OVER ([PARTITION BY expr] [ORDER BY expr])
> ```
>
> **示例**
> ```sql
> SELECT ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rank
> FROM employees
> ```

**边界情况处理**：
- 无返回类型时，不显示"返回类型"行
- 无示例时，不显示"示例"段落
- 函数名是关键字也视为关键字（如 `SUM`），但函数悬停优先匹配（解析器顺序已保证）

---

### 6.2 KeywordHoverResolver — 关键字悬停

**数据来源**：`src/languages/keywords/` 目录，合并规则为：
```
dialectKeywords = baseKeywords + dialectSpecificKeywords
```

**合并策略**：方言特定定义覆盖基础定义（同名关键字以方言版本为准）

**Markdown 渲染模板**：

```
### {KEYWORD}
---
{category_label} — 关键字

{description}

**语法**
\`\`\`sql
{syntax}
\`\`\`

**示例**
\`\`\`sql
{example}
\`\`\`
```

**示例效果**（悬停在 `LATERAL VIEW` 上）：

> ### LATERAL VIEW
>
> ---
> hint — 方言特有关键字（Hive/Spark）
>
> 与表生成函数（UDTF）配合使用，将一行拆分为多行
>
> **语法**
> ```sql
> SELECT ... FROM table LATERAL VIEW udtf(column) alias AS col_alias
> ```
>
> **示例**
> ```sql
> SELECT movie, category
> FROM movies
> LATERAL VIEW explode(categories) t AS category
> ```

**示例效果**（悬停在 `JOIN` 上）：

> ### JOIN
>
> ---
> join — 关键字
>
> 用于根据两个或多个表之间的相关列来组合行
>
> **语法**
> ```sql
> SELECT ... FROM table1 [INNER|LEFT|RIGHT|FULL|CROSS] JOIN table2 ON condition
> ```
>
> **示例**
> ```sql
> SELECT a.name, b.order_id
> FROM customers a
> INNER JOIN orders b ON a.id = b.customer_id
> ```

---

### 6.3 ParameterHoverResolver — 参数引用悬停

**触发条件**：鼠标悬停在 `${paramName}` 格式的参数引用上

**实现逻辑**：
1. 使用正则 `\$\{(\w+)\}` 检测光标处是否为参数引用
2. 提取参数名后，扫描整个文档匹配所有同名引用
3. 收集所有引用的行号和上下文
4. 构造悬停内容（含引用位置列表）

**Markdown 渲染模板**：

```
### 参数引用
---
**参数名** \`{paramName}\`

该参数在以下位置被使用（共 {count} 处）：

{location_list}

---
*提示：使用 "SQL-All-in-One: 替换 SQL 参数" 命令可批量替换*
```

**示例效果**（悬停在 `${start_date}` 上）：

> ### 参数引用
>
> ---
> **参数名** `start_date`
>
> 该参数在以下位置被使用（共 3 处）：
> * 第 12 行: `WHERE dt >= ${start_date}`
> * 第 18 行: `AND create_time >= ${start_date}`
> * 第 45 行: `HAVING min_date >= ${start_date}`
>
> ---
> *提示：使用 "SQL-All-in-One: 替换 SQL 参数" 命令可批量替换*

**性能优化**：
- 参数扫描结果以文档 URI + 版本号作为缓存键
- 仅在文档内容变更后重新扫描
- 引用超 20 处时，仅显示前 20 处并附加 `... 还有 N 处` 提示

// 新增 HoverProvider 注册
const hoverProvider = new SqlHoverProvider();
for (const lang of sqlDialects) {
    context.subscriptions.push(
        vscode.languages.registerHoverProvider(
            { language: lang },
            hoverProvider
        )
    );
}

// 配置变更监听（运行时启停）
context.subscriptions.push(
    vscode.workspace.onDidChangeConfiguration(e => {
        if (e.affectsConfiguration('SQL-All-in-One.enableHover')) {
            // provideHover() 内部检查配置，无需重新注册
        }
    })
);
```

## 十、性能设计

| 策略 | 说明 |
|------|------|
| **关键字缓存** | 首次访问某方言时合并 baseKeywords + 方言关键字，缓存到 `Map<SqlDialect, KeywordInfo[]>` |
| **函数签名复用** | 直接引用现有函数签名数据，不重复加载，O(1) 查找 |
| **参数扫描缓存** | 以 `{uri}#{version}` 为缓存键，文档未变更时直接复用上次扫描结果 |
| **Markdown 按需构建** | 不预构建 MarkdownString，仅在触发 hover 时即时生成 |
| **提前短路** | `enableHover` 为 false 时直接返回 null，零开销 |
| **引用截断** | 参数引用超 20 处时仅显示前 20 处，避免超长 hover |
